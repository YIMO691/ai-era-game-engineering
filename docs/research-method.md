# 研究方法

研究单位是一个可回答、可证伪的问题，而不是一套新的能力框架。沿用[思想基线](manifesto.md)作为起点，但不把其中的 L1–L4 当作行业标准。两份报告的来源缺口见[导入说明](import-notes.md)。

## 最小闭环

1. **问题与范围**：明确要解释的现象、目标、对象、约束、非目标和验收条件。
2. **机制模型**：描述状态、数据流、所有权、生命周期和失败路径，标出尚未确认的假设。
3. **证据**：检索可定位材料，登记支持与反对信息，检查其版本和适用范围。
4. **候选方案**：至少比较基线与一个替代方案，说明成本、收益、风险和退出方式。
5. **验证**：先定义观测指标、测试条件和可能推翻假设的结果，再执行实验。
6. **结果与局限**：区分实际观察、因果解释与外推，记录失败、未运行项和环境限制。
7. **后续问题**：说明哪些判断需要修订、还缺什么证据，以及下一次最小行动。

## 如何描述证据

| 类型 | 写法要求 | 不能替代什么 |
|---|---|---|
| 来源事实 | 给出版本、原文定位与可核查出处；未核验时明确标记 | 不以“官方”二字代替内容核对 |
| 特定案例 | 写明项目、条件、指标口径及发布者身份 | 不直接推出普遍最优，不冒充本项目实验 |
| 综合推论 | 列出依据、推理过程、适用范围和可能反例 | 不伪装成来源原话或行业标准 |
| 待验证假设 | 给出预测、观测方法与否定条件 | 不提前写成事实或实验结论 |

证据身份与证据适配性分开判断。官方文档、项目文档或源码可用于说明机制、设计目标及特定版本行为；它们不会自动证明性能优越或普遍有效。效果主张应审查实验设计、基线、样本、测量口径与独立复查条件，不机械按来源身份排序。

每条外部材料在[来源登记](../research/sources.md)中记录完整字段。没有 URL 或无法定位原文时保留“未核验”；找到相关新资料不等于恢复原报告引用映射。原任务书未提供，不推测其完整要求。

## 实验最低记录要求

性能记录至少包含 Unity、运行时及包版本，设备和系统，构建配置，场景与负载，基线，测量工具和采样方法，重复次数，前后原始数据及汇总口径，以及限制。移动设备还应记录温度、运行时长、分辨率和缓存等可能影响结果的条件。Editor 结果与目标设备结果分开记录。

正确性实验先写不变量与失败矩阵，例如旧场景任务不能修改新场景状态、对象销毁后的回调不能继续访问无效对象。覆盖正常完成、销毁、取消、超时、重入和异常；具体机制须由版本资料及实际实验确认，不预设某个 API 自动解决问题。

比较方案时控制变量，记录失败和无收益结果。数据不足就报告“不足以判断”，不把一次成功外推为稳定保证。不创建实验数据占位来模拟测量。

## 可复制的研究记录

下列文本可复制到真正开始的研究记录中；届时把首行设为该文档唯一的 H1，按需要删减字段，不预建空目录。

```text
题目：一个窄问题
状态、日期与记录者：
问题与目标：要回答什么；成功或失败如何判断
范围与非目标：Unity/C# 版本、对象、平台与限制
机制模型：状态、数据流、所有权、生命周期、失败路径
证据：来源登记编号、原文定位、核验状态、支持与反证
判断类型：哪些是事实、案例、推论、假设
候选方案：基线、替代方案、代价、风险、回退方式
验证设计：不变量、指标、步骤、否定条件、重复次数
环境：版本、设备、构建配置、场景、测量方法
实际执行：命令或操作、退出码、输出或数据文件
结果：前后数据、观察与解释；未运行项及原因
局限：混杂因素、证据缺口、不可外推的范围
AI 参与：工具或模型、任务及可写范围、实际改动
人工判断：审查范围、接受或拒绝原因、剩余风险
修订与后续：新证据、影响范围、修改原因、下一步
```

AI 生成的方案和代码也是待验证产物。记录实际执行命令与结果，而不是复述 AI 的完成声明；明确人工审查、权限边界和回退方式。尚未执行的检查不能写为通过。

## 何时更新结论

关键来源被证伪、版本变化影响机制、出现新实验或反例时更新，并保留原判断及修改原因。只根据已取得的证据修订能力判断，不以技术清单长度或生成代码量评价成长。不为活跃度更新，不承诺定时任务或会话外持续执行。
