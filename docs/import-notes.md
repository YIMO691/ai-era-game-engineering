# 导入记录与证据缺口

## 两份材料的角色

用户选择 `deep-research-report (2).md` 作为[思想基线](manifesto.md)，将 `deep-research-report (1).md` 作为[历史草稿](historical/deep-research-draft.md)。两份全文保真导入，不在原文中添加前言、替换引用或修订措辞；角色、字节数、SHA-256 与精确检查例外登记在[导入清单](imports.json)。

| 材料 | 当前用途 | 模型与版本边界 |
|---|---|---|
| 思想基线 | 研究宗旨与初始判断 | L1–L4：实现者、模块负责人、系统工程师、技术负责人 |
| 历史草稿 | 保留早期论证与分歧以便追溯 | L1–L5 仅为历史模型，不作为现行评估标准 |

L1–L4 是思想基线，不是行业标准、职业认证或已经验证的评分量表。两套模型不做机械映射、不合并，不再生成额外框架。基线自带的 v1.0 / 2026-10-29 是报告标记，不是本项目完成研究或发布的版本号。

## 已知证据缺口

- 基线与历史草稿分别包含 53 处、40 处导出引用标记，但均无字面 HTTP(S) URL。这些标记只是原导出痕迹，不能当作可访问来源。
- 两份报告提及的原始研究任务书未提供，不能据此声称已核对任务书要求或研究过程。
- 报告中的机制描述、案例、性能数字、AI 效率结论及来源归属均未在本项目中独立核验。
- 原文自称采用一手资料、交叉验证或“真实案例”，不等于本项目已经完成这些工作。
- 保存全文不代表同意全部观点，更不代表确认其真实性、普遍适用性或第三方材料再分发权。

原文中的 Mermaid 与引用标记按原样保存，未验证图形语法和实际渲染。新文档不复制导出引用标记。

## 如何处理后续证据

先在[来源登记](../research/sources.md)记录主张、报告位置、候选资料与缺失字段，再按[研究方法](research-method.md)判断证据能支持什么。

新找到相关资料，只能说明获得了新的支持或反证；除非能证明对应关系，不能称为“恢复了原报告引用”。第三方报告的数据也不能转写为本项目的测量结果。无法恢复的来源继续标记未核验，不猜测 URL、作者或数字口径。

发现错误时，在独立研究记录中给出更正、证据、影响范围和修改原因，保留原导入件及其身份。如果出现隐私或权利问题，应先停止相关材料的公开传播并处理，不以保真要求为由继续发布。
