# 在 Obsidian 中阅读

## 一份正文，两个入口

公开仓库保存可公开的研究正文，GitHub 以 [README](../README.md)为入口；本地 Obsidian 入口只是导航，不复制正文。不引入同步副本、插件、数据库、Publish 或额外服务。

若仓库作为笔记库的子目录使用，可在笔记库根目录打开 `00-AI时代游戏客户端工程研究.md`。该本地导航含 title、tags、status 属性，以完整库相对 wikilink 指向仓库内文档。它位于仓库之外，不是公开仓库的依赖；独立获取仓库的读者直接打开 README 即可。

## 链接约定

- 公开文档使用简单标准 Markdown 文件级相对链接，路径相对于当前文档。
- 不使用参考式链接、标题片段或 wikilinks；只有仓库外的本地入口使用 wikilinks。
- 不依赖同名笔记自动解析，不把私有笔记、笔记库外路径或本机绝对路径写入公开正文。
- 文件重命名时同步修订公开链接和本地入口，再运行检查，不假定编辑器能处理所有引用。

## 私有与公开边界

只发布独立仓库中经过审查的内容，不上传整个笔记库。私有研究、真实业务工程、本地配置与凭据不得复制进仓库。未确认权利的第三方全文和素材也不加入，许可范围见 [LICENSE](../LICENSE)。

公开页面应能在不访问本地笔记库的条件下独立阅读。忽略规则只能减少误纳入，不能代替文件清单与内容审查。

## 手动阅读验证

已核对 GitHub API 返回的 README HTML，以及本地入口的 10 个链接目标；这不等于视觉验收。目前未确认 Obsidian CLI 可用，Obsidian 阅读视图、浏览器视觉效果及 Mermaid 图形仍未验证。不修改插件或配置以强行开启接口。具备本地应用时按以下顺序检查并记录实际结果。

1. 在 Obsidian 打开本地导航，确认属性和所有完整库相对链接指向预期文件。
2. 从 README 依次打开思想基线、导入说明、研究方法、来源登记和路线图，检查相对链接。
3. 切换阅读视图检查中文标题、表格和代码围栏；确认没有意外创建同名空笔记。
4. 单独查看两份原文中的 Mermaid。即使文档检查通过，也不代表 Mermaid 语法或图形已验证。
5. 在 GitHub 实际页面另行检查 README 与导航。某一端成功不代表另一端成功。
6. 记录应用版本、检查日期、已看过的页面和未验证项；发现问题时区分链接结构错误与渲染差异。

自动检查要求见[贡献指南](../CONTRIBUTING.md)，报告来源边界见[导入说明](import-notes.md)。
