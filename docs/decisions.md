## D-001 直接改写专题主文档

- **背景**：所有者要求逐个优化专题观点的呈现。专题文件当时是带哈希的导出快照，另建精编版可以不触碰原文，但会让同一内容出现两份。
- **决定**：所有者在决策卡中选择“直接改写专题原文”。各专题主文档合并了状态说明、增加了“本节结论”，先前新增的精编版撤下。
- **后果**：公开文件与导出清单中的哈希不再一致，改动记在各清单的 `public_revision` 中。这也直接引出 D-002。
- **放弃的替代方案**：新增精编版阅读层，原文不动。

## D-002 公开仓库成为唯一编辑源

- **背景**：原约定是“私有研究版本是编辑源，公开区是授权快照”。D-001 之后，公开区事实上已经与私有稿分叉；长期知识库需要只有一个可修订、可检查、可引用的地方。
- **决定**：所有者在决策卡中选择“公开仓库成为唯一编辑源”。今后的修订和新增都直接在本仓库进行，私有研究稿冻结为历史档案。
- **后果**：导出清单只作来源追溯，不再要求哈希一致；[发布说明](../archive/research/PUBLICATION.md)中关于编辑源的条款被取代，隐私、排除与授权边界继续有效。专题元数据的 `edit_source` 统一为 `public`。
- **放弃的替代方案**：继续以私有稿为准，并把公开区的改写手动同步回去；或按专题分别决定编辑源。

## D-003 引入专题元数据、命题登记与生成的知识地图

- **背景**：仓库要承载长期、多维的知识。六个专题之间的关系、证据状态和成熟度原来只写在散文里，专题增多后无法检查是否一致。
- **决定**：每个专题新增 `meta.json`；新增 `knowledge/` 目录，存放受控词表、跨专题命题登记，以及由二者生成的知识地图；检查器校验这些数据，并拒绝过期的知识地图。设计见[知识库架构](../archive/docs/knowledge-architecture.md)。
- **后果**：新增或修订专题时，需要同步维护元数据与命题。维护成本若超过收益，按架构文档第 12 节收缩。
- **放弃的替代方案**：按维度复制目录（例如按证据等级分文件夹），会让同一文件出现多份；引入外部静态站点或数据库，会增加依赖，也违背检查器无需安装依赖的约定。

## D-004 本轮不移动目录

- **背景**：专题内部目录不统一，`docs/` 同时承载方法与研究产出。移动文件会打断外部链接，也会让正在审阅的 PR 难以比对。
- **决定**：本轮只新增文件和数据，不移动、不重命名已有文件。可能的移动列为[知识库架构](../archive/docs/knowledge-architecture.md)第 11 节的 P1、P2，由所有者决定。
- **后果**：短期内目录结构仍保留历史形态，靠知识地图与元数据弥补可查找性。

## D-005 把仓库整理成一本书

- **背景**：知识库骨架（D-003）完成后，所有者看了整体效果，要求整理文档、退役不需要的部分，“把这个仓库当成一本书去写”，方便他人和自己阅读与思考。所有者的这一要求同时回答了 D-004 留下的“是否移动目录”问题。
- **决定**：
  - 正文整理为 `book/`：前言、四部分八章、附录A–H。每章增加导读、小结与上下章链接，去掉重复的导出与修订说明以及 YAML 元数据。各章观点与证据状态不变。
  - 其余文件移入 `archive/`：保留原目录结构与相互链接，并在[研究档案](../archive/README.md)中逐份写明退役理由。
  - 退役 D-003 的机器可读层（专题元数据、受控词表、命题登记数据与生成的知识地图）。命题内容改写为面向读者的[附录C](../book/appendix-c-propositions.md)，检查器相应精简为“目录必须覆盖全书”。
  - 首页改为书的封面与目录。
- **后果**：
  - 外部指向旧路径的链接会失效，可以通过 Git 历史找回。
  - 正文引用的来源与证据仍可点击到研究档案。
  - 今后新增内容按[贡献指南](../CONTRIBUTING.md)中“本书的结构与修订”进行。
- **放弃的替代方案**：
  - 保留专题目录，只加一个阅读顺序页：读者仍要面对近百份并列文件。
  - 保留机器可读层：对读者帮助有限，维护成本却随章节增加。
- **仍待所有者决定**：
  - 研究档案中的个别文件是否应回到正文。
  - 第1.1章 26% 与 19% 两个数字的处理方式（命题 K-018；目前已加编者注）。
  - 原工程判断专题 README 中的运行模型名，该文件已随退役移入档案。

## D-006 重新定义为成长之书

- **背景**：所有者把这本书定义为“AI 时代下一个 Unity 客户端逐步成长的思考与学习”，并要求加入“各种优化思路”。此前的书是一本论点之书，以“责任、证据、限度”为主题。
- **决定**：
  - 书名改为《一名 Unity 客户端工程师的成长：AI 时代的思考与学习》。“责任、证据、限度”从主题改为每学一项都问的三个问题。
  - [学习路线](../book/roadmap.md)从附录升为全书骨架，共八篇 89 个条目。
  - 已写成的八章按“篇号.序号”归入对应的篇：第一篇放方法类四章，3.1、7.1、8.1、8.2 归入各自主题篇。
  - 优化单独成为第四篇，包括新增的优化思维 OP1–OP7、补充的 P11–P13 和 R6，并在路线中设“优化线索引”。
  - 各条目只列核心问题，不预写正文，学习时逐项进行。
- **后果**：
  - 章节文件移入 `book/partN-*/`，全仓库链接与“第N章”引用自动改写为新编号；外部指向旧路径的链接会失效。
  - 尚无章节的篇不建目录，只在目录与路线中列出。
- **说明**：对“优化思路”的范围由编者推测：既指性能与内存，也指包体、加载、构建与迭代效率、架构与代码层面的优化，以及“该不该优化、做到哪里为止”的判断。所有者可以纠正。
