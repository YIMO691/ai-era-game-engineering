# 工程判断与人机协作：精编版

> **状态（一次说明，正文不再重复）**：本精编版整理自[工程判断与人机协作](../engineering-judgment/README.md)专题（v0.9，2026-11-06，awaiting_review，人工pending）。来源登记71项中read 32、access_failed 33、discovered 6；两个Unity/C#案例（C1 UniTask 2.5.10、C2 NGO 1.9.1）有固定源码、测试与公开讨论的静态阅读，未运行；AI部分只有两项研究正文已读；认知与学习文献只取得检索片段；C3–C6缺必要的一手材料。七个模型、Tier分级、十四域×五级和十二周训练都是待验证的设计。本精编版继承这些状态。观点标签含义见[精编版目录](README.md)。

## 一句话

**把知识转成判断的最小动作，不是再记一组设计原则，而是在具体任务中作出一个可反驳的预测，找能改变决定的证据，并在结果出来后更新一条带条件的规则。**

## 核心问题

“资深”到底差在哪里？工程判断能否拆解成可训练、可评价的能力？分析该做多深、何时停？AI时代人最需要强化什么，怎样让AI训练判断而不是代替判断？

## 观点体系

### 观点一：工程判断是有条件的能力表现，不是一种通用聪明 〔工作定义〕

**工程判断力**是在具体任务、系统、权限与约束下，建立足以行动的模型，选择会改变决定的证据，比较真实方案，作出可解释且可验证的决定，并依据结果更新条件规则的能力表现。

它依赖领域与代码库的熟悉程度、工具和信息环境，不是脱离上下文的单一素质，也不保证结果成功。本专题拒绝用工龄、职级或表达速度当作能力证据，并明确保留一个反方解释：成果可能主要来自领域知识与仓库熟悉，而不是通用流程。

为了让“资深”可以讨论，本专题把它拆成四个相互作用的部分：**资源**（领域知识、代码库熟悉度、过去的故障经验）、**操作**（构造问题、抓关键约束、因果推演、竞争解释、区分性检查、更新置信度）、**环境**（反馈速度与可靠性、信息权限、可试验空间）和**表现**（在规定任务中实际预测、修改、验证与交付的结果）。

### 观点二：两条真实源码发现：完成、消费、复用是三件事 〔源码，静态，未运行〕

1. **C1 UniTask：取消结果正确，不等于回收正确。** 在限定的DelayPromise取消路径中，取消包装绕过了带清理语义的底层结果读取，没有走到已读的归池路径；即时取消另有跳过归池的分支。这是控制流的静态观察，不是实测的内存泄漏。
2. **C2 NGO：收到生命周期通知，不等于实例可以立即复用。** 在常规动态对象路径中，handler可以把物理释放转成归池；但不同端的行为不对称，业务的despawn回调之后旧网络流程还有读取。更有训练价值的是反例：XML文档默认值与实际签名不一致；某个关服测试的第二次等待仍在检查客户端标记，说明测试的判定条件（oracle）本身也要审查。

**可迁移的知识**：读“结果”还要读“消费带来的清理副作用”；读“完成”还要读“调度者是否仍持有”。样例、注释、测试本身也要审查，不是因为官方不可信，而是每种证据支持的范围不同。

### 观点三：判断的最小结构是十个要素，小任务压成四问 〔综合模型M2〕

目标 → 上下文 → 约束 → 证据 → 假设 → 方案 → 权衡 → 决策 → 验证 → 复盘。先过硬门槛，再比较偏好；不确定性会改变选择时，就补检查。

小任务压缩为四问：**改什么／为何在这里／可能坏什么／如何知道没坏。** 团队共同语言应多用“已知、假设、硬约束、暂不处理、复查条件”，少用“优雅、先进、最佳实践”。

**判断质量不等于结果好坏。** 高质量的决策可能遇到低概率的坏结果；无依据的决策也可能碰巧成功。复盘同时检查过程质量、结果和运气，不按结果倒写当时的理由。

### 观点四：方案比较分四步，“不改”永远是候选 〔实践建议〕

1. **硬约束筛选**：协议兼容、资产所有权、隐私、持久化正确性、平台、授权边界。不满足就淘汰，不能用“速度得分高”抵消。
2. **最低足够方案**：保持现状、沿现有路径局改、加适配层、结构重做；只保留真实可交付的备选，不制造稻草人。
3. **关键质量场景**：用“旧客户端缺新配置字段时仍可进入主界面”代替“兼容性高”。
4. **敏感性检查**：需求只用一次、访问量小一个量级、维护者少一半、截止日期提前，结论会不会反转？会反转的条件写进决策记录。

多准则打分可以帮助显式化偏好，但“给所有指标打1–5分再求和”不是真理；安全门槛独立于总分。

### 观点五：分析深度由后果、影响面、未知性与可恢复性决定 〔综合模型M5〕

任一维度为高即升级，不取平均；不按代码行数、是否“只是配置”定级。分三档（Tier 1–3），每档规定最少产物、审查、验证、停止和升级条件。

- 修改背包空态文案：Tier 1，查绑定入口和本地化key即可，不要两份架构方案。
- 同一UI加“领取奖励”：即使几行，也涉及服务端确认、重复点击、重连和幂等，至少Tier 2；改结算协议或账本不变量则Tier 3。
- **诊断与实施分别分级**；从高档降级须由相关owner确认隔离证据。
- **风险矩阵是对话与分流工具，不是概率估计**，不要把序数相乘制造精度。
- **可回滚代码不等于可撤回损害**：支付、数据泄露、永久存档损坏不能靠代码回滚撤销。

与AI-CQEP的L/M/H对照见[术语与分级对照](../../docs/glossary.md)。

### 观点六：选下一条证据时问“它会不会改变我的选择” 〔实践建议〕

“这个检查的不同结果，会不会改变方案或风险控制？”若不会，它可能只是在增加安心感。例如UI过期回调：再画完整类图的价值，可能小于复现一次“打开→关闭→重新打开→旧请求完成”。

本专题给出了信息的期望样本价值（EVSI）的形式表达，但随即约束：效用、概率和样本质量未知时，用区间和“哪些结果会改变选择”来思考，**不要假造小数概率**。

**S1–S6停止规则**：理解够用；决策稳定（关键未知不再改变选择）；风险可控或被明确接受；验证可反驳核心错误；新增分析的边际收益低于成本；责任明确（未测项、残余风险、发布批准有人承接）。时间盒用于限制探索，但到期不能豁免高后果风险。

### 观点七：抽象、重构、技术债、性能的判断原则 〔实践建议〕

- **抽象**：共同外形不是共同原因。复制两段独立的展示逻辑可能比一个多布尔参数的“万能面板”更清楚；但复制两套资源释放或协议签名逻辑会放大维护风险。没有“出现三次就抽象”的定律。
- **重构不等于重写**：先描述当前具体损失，建立行为基线（表征测试记录旧行为，不证明旧行为正确），分开行为保持重构与业务纠错，找接缝逐步迁移；迁移终态包括删除双轨。
- **技术债**：管理未来变化成本，不做道德评价。优先处理正在反复付利息的、近期必经的、有不可恢复尾部风险的、以及有自然修复窗口的债务。
- **性能**：帧时间是分布，CPU与GPU可能流水；不把平均FPS当唯一目标，也不把单次p99当稳定真相。没有实测，只写“待验证的优化假设”。

### 观点八：源码阅读要把事实、意图、反事实和规则分开 〔综合模型M3〕

读陌生项目的顺序：先写要回答的决策 → 确认运行与版本 → 沿一条纵向功能线建“薄地图” → 深挖一个风险最大的交叉点 → 补横向比较 → 用测试或运行挑战地图。

从案例沉淀的规则应写成：**当【环境/约束】时，【策略】可能优于【替代】，因为【因果机制】；依据【版本/路径/历史/运行】，代价【成本】，除非【边界变化】；下次用【新预测】验证。** 不能只写“用token”“加接口”“所有池都一样”。

源码不等于需求、完整运行或作者意图；作者动机不明时，明确标为推断。

### 观点九：AI时代人需要强化的，是定义问题、因果模型、独立验收与风险责任 〔研究＋综合模型M6〕

已读的两项研究：Peng等的标准化JavaScript HTTP服务器任务中，完成者用时减少，但研究没有测量代码质量；METR 2026年的跟进研究中心估计显示耗时下降，但区间跨零，并披露了选择、完成、计时与产物方面的限制。**不同任务和终点不能合成一个“AI普遍快或慢”的结论。**〔研究〕

由此提出的协作模型：人先写目标、风险与预测 → 有界委派（明确读写执行联网范围与停止条件）→ AI给出附带事实、推断与未知的候选 → 外部oracle与实际验证 → 有权限的人批准 → 定期做不用AI的变式任务。

**独立性指错误来源尽可能不同，不是人与AI的身份标签。** 第二个模型、人工源码审查、独立需求测试、故障注入、目标运行观测、有权限的领域审查各自能增加什么、仍会遗漏什么，原文有完整的阶梯表。

关于长期技能：自动化偏差是“因自动建议而少查或错信”的风险；认知卸载是把部分工作交给工具，不必然有害。长期技能退化需要长期证据，本专题既不宣告必然，也不宣告不存在。

### 观点十：能力可以操作化，但量表与训练效果都待验证 〔训练设计M7〕

- **十四个能力域**分别观察（需求、项目、系统建模、源码、架构、模块设计、代码判断、技术决策、风险、Debug、测试、重构、交付、AI），一个人在不同域可处于不同等级，不贴一个总标签。
- **L1–L5行为锚点**：从“在明确指导下完成局部任务”到“在多系统与组织约束下领导判断、培养他人”。这是行为锚点设计，不是经效度验证的量表。
- **十二周起步训练**：陌生仓库、纵向调用链、设计理由、跨项目对比、review、方案与抽象、多因Debug、异步与生命周期、实测性能、渐进重构、AI与独立验收、综合新题与延迟迁移。
- 训练的核心循环：**事前预测 → 外部反馈 → 新题迁移**；晋级用多个未见任务、反例、独立审阅与延迟迁移，不以“做完十二周”自动晋级。

**最小个人系统：一张任务卡、一组真实证据、一条条件规则。** 先观察它是否改善实际预测、验证和交付，再决定增加哪些流程。

## 可以推翻或收缩本专题的结果

1. 控制熟悉度与领域知识后，候选的跨任务操作不再有贡献：缩小“通用判断”的主张。
2. 文档更完整，但预测、发现错误与迁移没有改善：说明流程主要改善了表达。
3. 更慢且没有减少高后果错误：删减流程；更快但漏掉关键风险：不算收益。
4. 规则只在原案例有效、变式失败：补边界，而不是怪学习者。
5. AI工作流提升当下产出但无辅助表现下降：重新分配探索与生成。
