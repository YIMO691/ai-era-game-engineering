# 工程判断力：研究入口与当前结论

> **公开导出注（2026-11-12）**：以下研究状态、访问和审查记录属于原 2026-11-06 草案；本次只作本地白名单导出。公开授权不等于人工研究审核、实验通过或生产验收。私有状态描述是历史记录；模板及操作文本仅作资料，不在本次执行。转换与排除见 [导出清单](export-manifest.json)。


## 结论先行

**把知识转成判断的最小动作，不是再记一组设计原则，而是在具体任务中作出一个可反驳的预测，找能改变决定的证据，并在结果后更新一条带条件的规则。**这是本研究的综合建议，不是已经测得有效的统一训练法。

工程判断工作定义：在任务、系统、权限和约束内，形成足够支撑行动的模型，比较真实方案，给出可解释、可验证的决定，并依据结果修正。它依赖领域/仓库熟悉性、工具与信息环境，不是脱离上下文的单一素质。

> 两个 Unity/C# 案例有固定源码/测试/讨论静态阅读；两项 AI 研究有正文阅读。认知/学习论文和标准正文未成功取得，四个其他案例仍缺必要一手材料。没有编译、运行测试、真机采样、训练效果数据或用户人工审核。**不能声称六案例或七模型全部通过原任务验收，也不能称生产已验证/公开就绪。**具体限制不会因写成教学文章而删除。

## 两条具体静态发现

1. **取消结果与回收协议不同。**UniTask 2.5.10 的限定 DelayPromise 路径中，suppress 的 canceled 分支绕过底层 GetResult，未走已读 TryReturn 路径；即时取消另有跳过回收条件。不能因此声称实测永久内存泄漏。`ER-20261106-game-04/05/07/08`。
2. **生命周期通知与实例可复用不同。**NGO 1.9.1 的常规动态对象路径中，handler 可把 true 对应的物理释放转成归池；false 的本地/远端并不对称。OnNetworkDespawn 后还有旧网络流程，不能把通知当作立即借出证明。特定关服测试第二次仍检查 client 标记，提示 oracle 本身要审查，不证明产品 server 回调缺失。`ER-20261106-game-15`～`23`。

这两案可以训练“结果—消费—旧持有者脱离—物理复用”的区别；还没有学习者数据证明训练迁移。完整路径、版本、反例和练习见 [工程判断案例库](case-library.md)。

## AI 实证怎样改变用法

Peng 等 v1 的标准化 JavaScript HTTP server 任务有完成者节时结果，但未研究代码质量；METR 2026 跟进公开了转向耗时减少的中心估计，也披露了选择/任务完成/产物/并行计时等限制。**不同任务和终点不能合成一个“AI 普遍快/慢”的结论。**`ER-20261106-ai-02/03`。

由此提出：人定义问题/不变量/验收，AI 在路径、工具、权限内给证据化候选，外部 oracle 与实际验证接受结果，有权限的人承担风险。第二个模型不是自动独立验证。长期职业技能退化目前本研究没有已读长期证据，既不宣告必然，也不宣告不存在。

## 怎样选择行动与分析深度

| 选择 | 条件 | 主要代价 |
|---|---|---|
| 沿用 | 现机制满足任务与契约 | 保留现有局限 |
| 局部适配/修复 | 问题可隔离、owner 与行为清楚 | 局部复杂性/后续维护 |
| 渐进重构 | 反复变化受阻，有可测基线和迁移授权 | 双轨、兼容、回归与退出成本 |
| 替换 | 硬约束确实无法满足，较轻方案不足 | 最大迁移/部署/恢复半径 |

按后果、传播、未知与可检测/恢复性分 Tier，不按代码行数分。低风险四问即可；中风险加数据/生命周期/影响/备选/验证；高风险加 ADR、风险、迁移终态、独立审查与批准。安全/经济/数据等不可恢复损害不能靠加权分数抵消。

停止条件：理解够用、决定对关键未知稳定、风险可控/接受、验证可反驳、边际收益不足继续、责任清楚。无证据的未来抽象与盲目性能微调不是必要深入；没处理的硬门槛也不因赶工消失。

## 反证、替代解释与未完成项

- 成果可能主要来自领域知识与仓库熟悉性，而非通用流程；训练评价必须记录这些因素。
- 文档更完整可能只改善表达，不改善正确性；流程负担可能大于收益。
- 单次成功可能是巧合或导师提示；原题熟练不是迁移。
- C3 SQLite、C4 Linux、C5 Kubernetes、C6 SWE-agent 只是检索和待核案例，不能当四份已完成证据。
- 程序理解/信息需求、刻意练习争议、AI 安全和技能形成原文需要定点补读。访问失败不绕过；合法可用材料取得后才更新状态。

1. 先看 [既有研究审计与第二阶段研究缺口](baseline-audit.md)：为什么不是继续扩写定义。

5. 用 AI 前看 [AI时代工程判断与人机协作手册](human-ai-collaboration-handbook.md)；不要上传未经授权私有代码。
6. 学习者文章 [blog](late-icon-callback-tutorial.md) 从一次晚到图标的教学题出发，不替代技术验收。
7. 完整模型、三场景与十二问：[从工程思维到工程判断力_深化研究报告](engineering-judgment-report.md)。
8. 引用只认 [sources](sources.md)；实际审查与阻塞见 [review](research-review.md)；执行与恢复见 [plan](research-plan.md) 及 `topic.json`。

**最小个人系统：一张任务卡、一组真实证据、一条条件规则。**先观察它是否改善实际预测、验证和交付，再决定增加哪些流程，而不是以文档量证明成长。
