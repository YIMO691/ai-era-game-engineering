# 从工程思维到工程判断力

> **公开导出注（2026-11-12）**：以下研究状态、访问和审查记录属于原 2026-11-06 草案；本次只作本地白名单导出。公开授权不等于人工研究审核、实验通过或生产验收。私有状态描述是历史记录；模板及操作文本仅作资料，不在本次执行。转换与排除见 [导出清单](export-manifest.json)。


## 0. 执行摘要、导航与验收边界

**核心工作定义（本研究提出）**：工程判断力是在具体任务、系统、权限与约束下，建立足以行动的模型，选择会改变决定的证据，比较真实方案，作出可解释且可验证的决定，并依据结果更新条件规则的能力表现。它不是“会说设计原则”，不是无条件的通用聪明，也不是能保证结果成功。

相对前阶段，本研究的增量不是更多“工程应有闭环”的论证，而是五项可检查的工作：

1. 用任务、所有权、时间与权威状态替代纯类图式项目理解。
2. 把源码行为、作者意图、研究者反事实和可迁移规则分开。
3. 用后果、传播、未知、可检测/恢复性决定分析深度和停止条件。
4. 把 AI 的时间、正确性、维护、学习和长期能力影响拆成不同问题。
5. 将训练变成“事前预测—外部反馈—新题迁移”的可观察产物，而非工龄/阅读量排名。

> **warning** — 这不是已全部验收的研究终稿
> 四份基线已全文阅读。C1 UniTask 2.5.10、C2 NGO 1.9.1 已读取固定源码、相应测试与公开讨论，但未运行。AI 部分只有两项研究正文成功取得；认知/学习文献只有检索片段，尚未成功取得正文。C3 SQLite、C4 Linux、C5 Kubernetes、C6 SWE-agent 未完成必要一手材料核查。
>
> 因此：七模型、训练体系、三场景和协议是**研究综合模型/实践设计**；部分得到静态案例适配，不是心理机制验证、训练因果验证、生产验证或国际标准。**“六个充分一手案例”和“七模型均获实际案例验证”的原始验收条件尚未满足。**没有编译、Unity PlayMode、真机测量、训练实验或用户人工审核。

## 1. 既有研究审计：从共同骨架走向任务动作

四份基线共 1,438 行已读，证据 `ER-20261106-base-01`～`04`。

- 《工程思维》提供七层分析视角与系统/教育背景。
- 《软件工程思维》提供九个横切机制及社会—技术、运行和演进责任。
- 《游戏工程》提供体验/运行/生产/在线/治理五个领域。
- 《工程-软件-游戏》提供六个检查维度与五闭环。

这些不是四套竞争的人才等级，应保留各自层次。共同骨架已经是目标→约束/模型→备选→验证→反馈。尚缺的是具体任务中“先查什么、何时信直觉、怎样反驳、什么时候够用”。

### 关键修订

1. 本地 `turn...search...` 标记不可继承为可核验引用，不因此断言所有原结论错误。
2. 认证/标准表达规范目标，不直接证明专家怎么想、某训练怎么生效。
3. ISO 25010 的基线表有混版风险；12207:2026 不能因常识只记得 2017 就否定。标准原文未读，当前修订状态是**索引提示、待条款复核**，`ER-20261106-std-01`～`06`。
4. 无来源的引擎“70/30”比例不保留；质量乘除式不拿来计算个人或产品质量。
5. 可逆性不能凌驾所有正确性：支付、数据泄露、永久存档损害不能靠代码回滚撤销。
6. 帧时间需看任务依赖/CPU-GPU 流水及实测分布；感知反馈、远端显示、权威确认分开，不把简化式当通用测量模型。
7. AI 相互赞同不是独立 oracle，也没有由短期卸载直接推出长期退化的证据。

详细定位与研究地图见 [既有研究审计与第二阶段研究缺口](baseline-audit.md)，原四文未修改。

## 3. 专家认知：机制候选、知识依赖与环境条件

### 3.1 不把“资深”当一种统一大脑

当前没有足够正文证据回答哪一个认知差异“最本质”。一种更可检验的分解是：

- **资源**：领域知识、代码库/业务熟悉性、工具经验、过去故障族、可获得文档与同事知识。
- **操作**：问题构造、抓关键约束、状态/因果推演、竞争解释、区分性检查、置信度更新。
- **环境**：反馈速度、反馈可靠性、信息权限、协作分工、可试验空间、交付和组织压力。
- **表现**：在规定任务与指导条件下实际预测、修改、验证与交付得怎样。

它们相互作用，不把“知识多→必然判断准”或“多走流程→必然判断准”当定律。不同子系统的表现可以不同。

### 3.2 认知概念落到可观察行为

下表是**操作化提案**。文献候选 `ER-20261106-cog-01`～`12` 全部只读到搜索片段，不能说它们已验证该表。

| 概念 | 任务中可观察什么 | 容易误认为什么 |
|---|---|---|
| Mental models / systems thinking | 能预测状态、所有权、时序和传播；遇反例修改图 | 画完整目录图就是理解 |
| Pattern recognition / tacit knowledge | 能指出关键线索与适用边界；区分熟悉/陌生任务 | 回答快/有自信就是专家 |
| Causal reasoning | 竞争原因及可区分观察；修复能改变机制 | 相关改动后暂不报错就是根因 |
| Analogical reasoning | 两案的因果关系对齐，主动找不相似条件 | 相同类名/模式名就直接套用 |
| Metacognition / bias checking | 事前记录未知、预测、可推翻条件 | 谦虚措辞/低置信度即准确 |
| Bounded rationality | 在信息与时间成本下选下一检查与停止 | 永远查完，或用赶工豁免风险 |
| Deliberate practice | 特定薄弱环节、独立判定、反馈与新题 | 工时、刷题数、源码阅读页数 |
| Reflection in/on action | 实施时更新假设；事后区分当时信息/后来信息 | 只写成功故事、倒写早已知道 |

隐性经验可通过预测、对比案例、导师边做边解释和错误恢复过程部分外显；但言语报告可能事后合理化，因此仍需行为与结果，不只听故事。Schön、Polanyi、Simon 的原著本轮未读，不以其权威替模型背书。

### 3.3 如何识别“真正重要”的变量

实践策略不是平均关注所有细节，而是找**会改变可选行动/风险控制的变量**。

C1 中，再背一遍 await 语法不如查“取消包装是否调用带清理语义的 GetResult”；C2 中，识别 destroy flag 在不同端如何传播，比从方法名推断含义更有决定性。这是具体案例观察，不是证明专家普遍遵循某个固定算法。

局部缺陷/架构/需求问题也不靠症状大小区分：

- 目标/验收自身冲突 → 先澄清需求，不以架构解决。
- 契约清楚、错误局限一条路径 → 优先局修。
- 同一变化反复跨模块破坏不变量，且局修无法合理隔离 → 才有结构改善依据。
- 同一症状可有多原因，不能看见重复代码就宣布架构根因。

## 4. 七个研究综合模型：定义、输入输出与验证边界

以下都是**本研究综合模型**，不是国际通用标准、认知阶段定律或经验证量表。

### M1. 专家工程认知模型

- **问题**：信息不全时如何形成可修正的问题空间。
- **组成/关系**：感知症状↔构造问题↔激活经验↔建立系统模型↔生成假设/推演后果↔比较/决策→验证→反思更新；经验识别可以跳跃，反证可回到任一环；不预设严格线性。
- **输入/输出**：任务、知识/熟悉性、信息环境、线索 → 带证据等级的系统模型、候选解释、关键下一检查、预测与更新。
- **适用/局限**：适合可核查的诊断/维护任务；长期架构收益反馈模糊、黑盒和缺权限会限制；不能分离出未经测量的“纯通用脑力”。
- **案例演示**：C1 的三个“完成/消费/可复用”与 C2 的角色/入口反例，显示模型应包含什么；**没有观察真实专家思考过程**。
- **训练/评价**：隐藏实现先预测，逐步给证据；检查预测准确与改判依据、提示依赖、任务熟悉性。需真实研究才能判断训练效果。

### M2. 工程判断模型

- **问题**：把偏好转为可解释行动。
- **组成/关系**：目标—上下文—约束—证据—假设—方案—权衡—决策—验证—复盘；先硬门槛，后偏好；不确定会改变选择则补检查。
- **输入/输出**：任务、版本、权限、后果与事实 → 条件化决定、最小实施边界、验收/恢复、残余未知和负责人。
- **适用/局限**：小任务四问即可；质量属性评分不能遮蔽不兼容/安全硬门槛，不保证结果。
- **案例演示**：C2 handler true 与 authority false+手动回池，是在不同角色责任下比较真实方案，而不是“对象池总更好”。
- **训练/评价**：对相同约束列备选并预测失败；看是否捏造选项/分数、是否被反例改判。详见 [工程判断模型与决策手册](decision-handbook.md)。

### M3. 源码阅读知识转化模型

- **问题**：从知道做什么走向知道为什么/何时可迁移。
- **组成/关系**：任务问题→版本事实→行为/owner→意图证据→替代/反事实→条件规则→新题预测→验证更新；没历史就保留推断。
- **输入/输出**：固定源码/测试/历史与具体问题 → 可追溯案例卡、条件规则、不可照搬项。
- **适用/局限**：维护/对比阅读；动态内容、原生黑盒、服务端和部署不在可见源码内，静态不能取代运行。
- **案例演示**：C1 README 的取消成本理由与研究者对归池条件的解释分开；C2 XML 与公共签名冲突。
- **训练/评价**：逐步开放材料，独立反事实与近迁移；不按读文件数评分。详见 [成熟项目源码阅读与设计还原手册](source-reading-handbook.md)。

### M4. 成熟项目适配模型

- **问题**：在交付约束下理解并克制地修改已有系统。
- **组成/关系**：锚任务→薄纵向图→owner/不变量→相邻范例与例外→传播影响→沿用/适配/局改/重构→小步验证→经验回填。
- **输入/输出**：任务/仓库版本/平台/权限/时间 → 足够地图、最小 diff、兼容/回归、后续债务。
- **适用/局限**：既有系统变更；规范需契约/门禁/维护者证实，出现次数多不等于正确。不授权任意重构。
- **案例演示**：C2 先沿用实际 handler 机制而不是绕开 NGO 网络生命周期；本报告 §7 的教学场景。
- **训练/评价**：给陌生模块小需求，检验地图能否预测真实影响及非代码依赖，而非是否重画“理想架构”。

### M5. 工程决策深度模型

- **问题**：避免匆忙与过度分析。
- **组成/关系**：后果、传播范围、未知、可检测/恢复性→Tier→最有区分力的证据→S1–S6 停止/升级；不可恢复损害优先门槛。
- **输入/输出**：失败情景、环境/影响、恢复条件、证据成本 → 分析/审查/测试深度、停止或升级决定。
- **适用/局限**：不是行数/职位/序数相乘打分；概率缺失时不用伪精确 EVSI；时间盒不是风险豁免。
- **案例演示**：C1 只改取消包装也可能改变回收；C2 公共池回收不能按“一行代码”定低风险。并未测得 Tier 的最优收益。
- **训练/评价**：同一 UI 文案与奖励结算做不同级别；要求解释升级与停止，统计负担。详见手册的 Tier 全矩阵和停止规则。

### M6. AI 人机协作模型

- **问题**：有界委派并保留人类理解/责任。
- **组成/关系**：人定义目标/先验→权限合同→AI 证据化候选→外部 oracle→人批准→反馈/无辅助迁移；不是多模型投票。
- **输入/输出**：任务/版本/Tier/许可上下文/验收 → 最小可审查产物、真实验证、限制和风险接受。
- **适用/局限**：AI 能否节时受任务与审核成本影响；人无能力审核时应缩小范围/求助，不能用模型自信兜底。
- **案例演示**：用 C1/C2 源码训练 AI 契约审查；C6 SWE-agent 只能提供待核框架，**不构成已完成真实工具案例验证**。
- **训练/评价**：人先预测、AI 反方、独立反例、无 AI 变式；分测时间/正确性/维护/学习。详见 [AI时代工程判断与人机协作手册](human-ai-collaboration-handbook.md)。

### M7. 工程能力成长模型

- **问题**：让工作经验变成可检验的能力变化。
- **组成/关系**：任务→独立表征/预测→行动→可归因反馈→差异解释→条件规则→间隔后变式任务→更新；导师提示逐步撤除。
- **输入/输出**：能力域基线、任务难度/熟悉性、指导条件、外部反馈 → 多任务行为证据、下一薄弱项，不是统一“能力指数”。
- **适用/局限**：可用练习/真实授权任务；无对照不能归因训练，短期保持不等于远迁移；L1–L5 和晋级门槛未经效度验证。
- **案例演示**：C1/C2 提供隐藏答案/边界变式材料；**没有学员数据，不能称成长模型已被案例验证有效**。
- **训练/评价**：十四域分别用行为锚点评分，多个新任务/独立审阅/延迟迁移，记录流程成本。详见 [工程判断力训练与能力评估手册](training-and-assessment-handbook.md)。

## 5. 从源码理解到设计理由：两条真实静态发现

### 5.1 C1：终态正确不代表消费/回收正确

UniTask 2.5.10 固定 SHA `7c0f199fe0d3fc528024488ccd671e6c7b27745b`。取消包装 canceled 分支绕过底层 GetResult；在限定 DelayPromise 中途取消路径，未走到已读 TryReturn 路径。即时取消另有特定跳过归池分支。证据 `ER-20261106-game-04/05/07/08`。

这是控制流/协议的静态观察，不是实测内存泄漏。README 对轮询/registration 和异常成本有直接理由；对具体归池条件未找到作者说明。既有取消测试检查 bool/异常/帧差，不足以证明本案 source 归池。

新增知识：读“结果”还要读“消费带来的清理副作用”，读“完成”还要读“调度者是否仍持有”。适配器与对象复用都可能隐藏这种区别。

### 5.2 C2：回调发生不代表旧持有者不再访问

NGO 1.9.1 固定 SHA `7d27c5141123e3b9f31419ccca7768a640a45d56`。正常动态对象、指定入口下，true 可委托 handler 归池；false 在 authority 与远端的物理释放并不对称；业务 OnNetworkDespawn 后旧网络流程还有读取。证据 `ER-20261106-game-15`～`20`。

更强的训练材料是反例：XML 默认值与实际签名不一致；便利入口打破“handler Instantiate 永不在 host”泛化；特定关服测试第二次等待仍检查 client 标记，不足以独立证明 server 侧。`ER-20261106-game-23`。

新增知识：**样例、注释、测试本身也要审查，不能只审实现。**不是“官方不可信”，而是每种证据支持不同范围。

### 5.3 源码阅读的产物

一条好规则写成：当【环境/约束】时，【策略】可能优于【替代】，因为【因果机制】；依据【版本/路径/历史/运行】，代价【成本】，除非【边界变化】；下次用【新预测】验证。

不能只写“用 token”“加接口”“所有池都一样”。完整六案及四案缺口见 [工程判断案例库](case-library.md)。

## 6. 成熟项目决策、复杂度与停止

### 6.1 四种行动不是价值高低排序

- **沿用**：现机制满足契约，风险受控，不为个人偏好改风格。
- **适配**：目标可在现边界实现，局部 adapter 封装差异，并有明确 owner。
- **局部改进**：缺陷/变化明确局限，可建立行为基线。
- **渐进重构/替换**：现结构反复造成真实成本或硬约束无法满足，且有隔离、迁移、回归与授权；替换是更重选项，不是默认。

抽象看共同变化原因与不变量，而不是出现次数；债务看实际利息、近期变化、后果与修复风险，不把“代码旧/丑”道德化。性能优化以目标环境已测瓶颈开始，以达标/无重要回归/边际收益不足结束。本轮没有 profile 数据。

### 6.2 风险比例化协议

| Tier | 典型触发 | 最少产物 | 审查/验证 | 升级 |
|---|---|---|---|---|
| 1 | 真正局部、可检测可恢复、无敏感状态传播 | 四问短卡、最小 diff/结果 | 局部契约与相关边界，不强行两方案 | 发现跨模块/owner/版本未知或高后果 |
| 2 | 新状态/异步/配置/协议交互、多模块 | 数据/生命周期、影响、备选、验证矩阵 | 相邻 owner 审查，正常+失败/乱序/回归 | 改公共基础设施、持久数据/经济等关键不变量 |
| 3 | 公共架构/资源/网络核心/持久化/热更新/大迁移 | ADR、风险、分阶段与终态、独立验收/恢复 | 相关领域/授权者，混合版本与故障/恢复 | 无法控制则分拆/停止/补证，不继续堆方案 |

不是按模块名机械划档：一处共享文档笔误不等于高风险；一行经济发放可以高风险。诊断与实施分别分级，普通原因竞争不自动升最高档；关键契约无法确认且潜在损害不能界定或隔离时先升级审视，实施前按证据重评。高档降级或裁剪需相关 owner 确认隔离证据。完整八项字段（触发/必需/可选/产物/审查/验证/停止/升级）见决策手册。

### 6.3 停止与下一条信息

S1 理解够用；S2 关键未知不改变选择或有条件决策；S3 风险可控/被明确接受；S4 验证能反驳核心错误；S5 新增分析/优化收益不抵成本；S6 责任与未测项有人承接。

EVSI 的形式表达可帮助问“拿到什么结果会改选”，但本包没有概率/效用数据，不能算精确期望值。不要把风险序数相乘制造精度。硬门槛未满足时，即使时间盒到期也不能默许发布。

## 7. 三个成熟 Unity/C# 项目推演

> **example** — 三个场景的身份
> 以下是**抽象商业项目的教学推演**，不是访问公司工程后的案例观察。所有项目约定均是显式题设，所有证据采集与测试都是待执行方案，没有伪造代码、日志、性能值、测试通过或交付结果。它们不能补足 C3–C6 的一手研究缺口。

### 场景 A：在既有系统新增“活动奖励预览与领取”

**题设与目标**：已有活动服务、背包状态、配置/资源、UI 框架；服务端负责结算。新增预览与领取，不更改奖励账本和网络协议；若现协议不足则升级任务。成功是显示与服务器确认一致，失败/重试不重复发放；不是“按钮能点”。

**探索与待查证据**：沿入口→配置→活动请求→服务端回包→背包更新→UI 反馈→关闭追一条薄线；查当前版本一次成功、拒绝、超时/重连路径，配置/本地化/图标引用、业务幂等键和发布顺序。不能用相似面板类名代替确认这些契约。

**系统模型**：UI 有展示/请求资格，活动服务协调，服务器为结算权威，背包模块存客户端同步状态，资源服务拥有句柄契约；UI 关闭不撤销已在服务器完成的领取。

**风险与分级**：至少 Tier 2。重复点击、晚到回包、关闭重开、配置不存在、旧客户端兼容；若要改变经济结算或持久化不变量则 Tier 3。不能按几行按钮代码定 Tier 1。

**真实备选与决定（依据题设）**：A 沿用活动服务、局部面板逻辑；B 建通用活动工作流；C 重写资源/消息框架。题设没有跨活动稳定共同变化证据，选 A；B 只在已证共同契约与未来确定变化时重评；C 超出目标且扩大回归。若现服务不满足幂等/确认语义，则先澄清协议，不用 UI 防抖冒充完整幂等。

**实施边界**：只改活动表现/现服务适配/配置与必要测试；不改账本、公共资源 API。区分本地“请求中”与服务器“已领取”，失败保持可解释状态；关闭后禁止旧结果写入新的展示代次，结果/资源仍按实际 owner 清理。

**验证计划**：有效/无资格/已领取/超时/重复/乱序/重连/关闭重开；旧新配置与资源缺失；按项目实际兼容组合检查。oracle 是服务器确认与背包不变量，不是按钮颜色。构建后端/真机范围由实际风险确定，本轮未运行。

**停止与复盘**：目标/权威/不变量清楚、关键回归和失败控制满足、有权批准才交付；未知协议风险未解决就停止。复盘比较预期传播与真实变更，检查是否过度抽象、是否把关闭理解成撤销业务。输出一条“展示生命期不等于业务事务生命期”的带边界规则。

### 场景 B：修改有历史问题的可复用背包格子

**题设与目标**：格子复用，异步加载图标；有时晚到结果串位。旧资源 API 暂不能全项目替换。目标是修复当前格子生命周期，不承诺底层请求可中断，不顺手重写 UI 框架。

**探索与证据计划**：固定 UI/资源包版本，追 Bind/Unbind/启停/回池、请求完成、句柄转移/释放；搜相邻两个使用者和一个历史例外；控制 A 请求晚于 B 的完成顺序。先写“对象活着≠仍有写入资格”的预测，尚未运行。

**模型与原因竞争**：H1 旧回调写新绑定；H2 资源 key/config 错；H3 共享句柄提前释放。用请求身份+展示代次+资源 key+owner 的最小观测区分，不凭症状直接认定 H1。C1 提醒取消表达与回收分开，不证明本项目已经同一种 bug。

**方案比较**：A 现服务上局部绑定代次与晚到处置；B 旧 API 后建小适配器逐迁调用方；C 替换全资源系统。若问题只在该格子且句柄契约清楚，选 A；若多调用方同一缺陷反复出现、共享行为可测，选 B 并定义旧路终止条件；C 没有足够证据和授权。

**实施边界与责任**：新 Bind/Unbind 使旧写入资格失效；取消仅用实际 API 支持的语义。成功/失败/取消/晚到分别明确结果是否需 release，不能把共享资源无条件释放；不可为了补清理重复消费单次 awaitable。由现框架保证的事不再叠第二套 owner 服务。

**Tier 与审查**：H1/H2/H3 尚未分出，不自动等于 Tier 3。暂按 Tier 2 诊断的前提是后果和影响面已界定，且只读或隔离观测不会扩大损害；若共享句柄的 owner/关键契约无法确认、潜在损害又不能界定或隔离，则先进入 Tier 3 审视，暂停有害试验。实施前重新分级：资源 owner 确认句柄契约与局部影响后，局部修改可按 Tier 2；动公共资源/池/所有权契约则 Tier 3。降级或裁剪记录隔离证据及确认人，不只让 UI review 看画面。

**验证计划**：A→B→A 复用、关闭重开、同 key 重复绑定、成功/失败/取消交错、结果持有/释放计数；确认旧回调不改新代，且没有双释放/漏释放。静态正确还需运行和真实包验证，当前未做。

**停止与复盘**：错误因果已区分、最小修复有反例/回归、未测平台及旧调用方影响已明确；不以“本次没再串图”代替证明。复盘分开业务 bug 修复和行为保持重构；规则转移到其他复用对象前核查其实际资源契约。

### 场景 C：返回大厅再打开背包，出现长帧与偶发串图

**题设与目标**：跨场景流程涉及网络重连、配置/资源、事件/UI、对象池；需要定位并最小修复，不预设两个症状同一根因。无真实 trace/设备数据，所以输出的是完整**诊断与条件修复方案**，不是已定位结果。

**边界与基线**：先规定目标设备/构建/后端、内容版本、网络条件、操作脚本、预热和采样窗口；分别定义长帧分布/关键路径与图标正确性。保留已知好/坏版本，检查最近配置和代码变化。Editor 数据不能直接替代真机结论，候选 `ER-20261106-unity-01` 仍待正文核验。

| 竞争解释 | 预期证据 | 最小区分检查 | 条件修复，不是本轮结果 |
|---|---|---|---|
| H1 重连重复订阅，引发多次 rebuild | 同一事件/代次被消费多次，CPU/UI 工作重复 | 订阅/退订 owner 与事件关联 ID；对照无重连 | 修订阅生命周期，保留必要重放语义 |
| H2 资源/内容同步加载成为关键路径 | 对应阶段阻塞/依赖等待，缓存条件改变表现 | 目标构建 profiler+资源阶段标记，控制冷/热 | 改该依赖/预载策略，不先重写加载系统 |
| H3 复用对象旧回调串图 | 旧请求完成跨越新绑定代次 | 可控乱序与 key/代际观测 | 场景 B 的资格/owner 修复 |
| H4 GPU/渲染负载而非 C# 热点 | GPU/渲染路径与症状一致 | 保持业务路径，控制渲染/分辨率等变量 | 交相应渲染/内容 owner，不做无关微优化 |

**信息选择**：先做能区分 CPU/资源/GPU 与重复事件的最小采集，而非全仓库类图；观察有噪声、profile 有开销，使用一致条件的重复采样。日志本身不得记录私人数据或在热路径制造新瓶颈。

**方案与决定**：A 只凭串图给所有异步加 cancel；B 改整个资源/事件框架；C 先区分原因，再分别做最小修复。按题设缺证，选 C。若 H1/H3 均被各自证据支持，拆两个因果清楚的补丁和回归，不勉强凑单一“根因”。若任何假设未区分，继续最有信息价值的观测，不能把表格当结果。

**实施/风险**：不改重连协议/经济状态；必要公共契约变更升级 Tier 3。重复终止/重入/异步清理由唯一 owner 协调；网络池若相关，先按 C2 分角色/入口读真实版本，不套用回调名。性能改动不改变应有业务行为。

**验证与停止**：同脚本/设备/负载前后对照，检查分布和退化警戒、长帧阶段及图标不变量；恢复/重连/旧新内容回归。目标达标且无重要回归、有清楚残余风险即停止，不追求无上限微优化。若无稳定复现/测量，不发布“已优化 X%”。

**复盘**：哪些事前预测被否定？长帧与串图是否真的相关？补丁是否只压症状？观测环境/内容与玩家是否一致？沉淀“先分终点与竞争机制，再选采集与修改”的规则，在下一陌生模块上复测。

## 8. AI 时代：强化判断，不把时间收益等同整体价值

两项正文已读的限定研究发现：

- `ER-20261106-ai-03`：Peng 等 v1 的 2022 JavaScript HTTP server 实验，完成者时间比较报告 55.8% 耗时减少，95% CI [21%, 89%]；研究未测代码质量，不能推广为所有维护或学习收益。
- `ER-20261106-ai-02`：METR 2026-02-24 跟进，两个子集中心估计耗时下降，但区间跨零，并明确披露选择/完成/计时及产物差异，难以代表当前净效应。

因此人更需要清晰需求、因果与系统模型、版本/权限、独立验收和结果归因。不是说人必须比 AI 手写更快。AI 可搜索/列方案/写局部代码/生成候选测试，但不自动拥有业务意图、风险接受与发布权。

自动化偏差是“因自动建议而少查/错信”的风险描述；认知卸载是把部分工作交给工具，不必然有害。长期技能退化是需要长期证据的问题，不能从短期任务或非软件实验推定。安全/学习反向候选已保留，尚未读原文，不作确定结论。

最小协作：人先写目标/风险/预测→有界委派→AI 附事实/未知/路径→外部 oracle/运行/独立 review→有权限的人批准→定期无 AI 变式任务。完整矩阵和验收见 [AI时代工程判断与人机协作手册](human-ai-collaboration-handbook.md)。

## 9. 训练、评价与最小个人系统

### 9.1 不用年限评 L1–L5

十四个域分别观察：需求、项目、系统建模、源码、架构、模块设计、代码判断、技术决策、风险、Debug、测试、重构、交付、AI。一个人在不同域可不同级，不给人贴一个总标签。

- L1：在明确指导下完成局部任务并提供结果。
- L2：在清楚边界内独立，识别常见失败。
- L3：独立处理跨模块未知，比较真实方案与验证。
- L4：处理高风险演进，建立团队可复用的验证/决策支持。
- L5：在多系统/组织约束下领导判断、发现方法边界并培养他人。

这是行为锚点设计，**不是效度验证后的量表**。完整每域五级、指导/风险/方案/证据/错误/晋级在训练手册。安全/授权/真实性硬门槛不能用平均分抵消。

### 9.2 十二周起点

1 陌生仓库与基线；2 真功能纵向调用；3 理由与历史；4 跨项目对比；5 review；6 方案/抽象；7 多因 Debug；8 异步/生命周期；9 实测性能；10 渐进重构；11 AI+独立验收；12 综合新题/延迟迁移。

每周都有目标、少量输入、任务、证据、评价、复盘；详见手册。当前只是设计，没有学习者、通过率或效果。额外投入可与工作任务重合，不以额外文档量作为成绩。

六至十二个月：从一类故障/模块的可重复独立表现，扩展到不同模块/平台/发布，再到高风险演进与带教；晋级用多个未见任务、反例、独立审阅与延迟迁移，不以“做完十二周”自动晋级。

### 9.3 最小系统

**一张任务卡 + 一组真实证据 + 一条条件规则。**

Tier 1 四问；Tier 2 一页数据/owner/影响/备选/验证；Tier 3 才展开 ADR/风险/迁移与独立批准。记录应帮助当前或未来决定；没有用途的字段可删，不删关键风险/未运行事实。模板包不是新的审批平台。

## 10. 十二个问题的结论、证据、边界与行动

### Q1 资深工程师与普通程序员最本质的认知差异是什么？

- **结论**：不能据本轮证据给出单一本质。更可检验的是任务相关知识、系统/因果表征、证据选择和反馈更新的组合，且受环境支持。
- **证据**：C1/C2 显示需要哪些区别；cog-01/02/05/06 是未读正文候选，不能称已验证专家认知优势。
- **边界**：职级/工龄/表达快不是能力证据；熟悉系统成功不保证跨域。
- **行动**：对陌生任务先画 owner/状态/时序，记录哪条证据改变判断；同时记录熟悉性与指导。

### Q2 工程判断力能否拆解成可训练和评价的能力？

- **结论**：可以操作化为可观察行为；“拆解有效/训练有效/量表有效”仍待验证。
- **证据**：M2/M7 与十四域为本研究设计；没有训练实验。
- **边界**：不把 rubric 总分当稳定人格或员工排名，硬门槛不被补偿。
- **行动**：先选一个域、三个不同任务和外部 oracle，观察独立完成/反例/延迟迁移，校准评分。

### Q3 专家如何从有限信息识别真正重要的问题？

- **结论**：本研究建议优先会改变方案/风险控制的线索，围绕硬约束、owner、因果传播选区分性检查。
- **证据**：C1 的 GetResult 转发、C2 的角色/flag/调用顺序是具体决定性变量；cog 文献仍候选。
- **边界**：不能证明所有专家都以相同步骤思考；信息不可得时可能必须升级/延后。
- **行动**：写首选/备选及两种预期观测，问“下一检查能分清谁？”

### Q4 如何从源码学设计理由而非模仿？

- **结论**：先事实，再历史意图，再反事实和迁移边界；作者动机不明就明确推断。
- **证据**：C1 README 与归池解释的不同地位；C2 PR #977 和 XML/实现冲突，game-03/04/15/17/25。
- **边界**：源码不等于需求、完整运行或作者意图；旧版本机制不自动成立于新版。
- **行动**：每案写一个可行替代、代价、何时不采用现方案和一题新预测。

### Q5 成熟项目中何时遵循、适配、改进、重构？

- **结论**：以当前契约是否满足、问题范围、重复变化成本与隔离/验证能力选最小足够行动。
- **证据**：M4 为提案；C2 扩展点是具体契约；Kubernetes 演进正文尚未核验。
- **边界**：“项目一直这样”不是合理性证明；个人风格不是重构理由。
- **行动**：查不变量与相邻例外，列最小变更/适配/渐进方案和升级门槛。

### Q6 如何判断足够好、避免过度设计？

- **结论**：满足目标/硬约束、关键失败有验证与责任、方案对关键未知稳定后停止；不替未知未来付无限成本。
- **证据**：M5、S1–S6 是综合建议，method-01/02 正文未读，不能说已证明最优。
- **边界**：剩余不可恢复高风险不能因分析累了而忽略。
- **行动**：事前写验收/停止；每次追加抽象问实际变化原因与反例，删无决策价值工作。

### Q7 如何按风险、可逆性、影响面决定深度？

- **结论**：联合判断后果、传播、未知与检测/恢复条件，不把序数相乘当概率；由风险门槛升级 Tier。
- **证据**：C1/C2 的局部 API 改动可传播到回收；Tier 是本研究设计。
- **边界**：可回滚代码不等于可撤回经济、数据和玩家损害。
- **行动**：列最坏损害、owner、检测、隔离/恢复与恢复不了部分，再决定产物/审查/测试。

### Q8 如何把实践转成可迁移经验？

- **结论**：保留当时预测与真实结果，抽出带条件/机制/例外的规则，再在未见任务检验。
- **证据**：C1/C2 支持区别逻辑终态与物理复用的窄归纳；cog-10 等迁移原文未读，训练效果未知。
- **边界**：换变量名的重复题不是广泛迁移，成功结果不证明原理正确。
- **行动**：配一题表面不同机制相同、一题表面相同机制不同，延迟后无答案提示复测。

### Q9 AI 时代人类最需强化什么？

- **结论**：问题定义、上下文/约束、因果与所有权、独立验收、权限与风险责任。
- **证据**：ai-03 节时但未测质量；ai-02 显示真实工作效应与计时/产物不可简化。
- **边界**：不是声称人手写必须快于模型，也不是所有 AI 任务都更慢。
- **行动**：委派前写 oracle 和不变量，审查最危险边界而非逐字迷信解释。

### Q10 如何让 AI 训练判断而非代判断？

- **结论**：让人保留预测/比较/反驳/最终接受，并定期测无 AI 新任务；作为待验证设计。
- **证据**：M6/M7 提案；ai-08/09/11 相关原文尚未读，没有长期效果证据。
- **边界**：先写思考不一定提高净效益，需观察负担；无 AI 测试不应禁止正常查文档并退化成背诵。
- **行动**：人先判、AI 第二意见；或 AI 多案盲评；反方审查后用外部测试淘汰假阳性。

### Q11 Unity/C# 客户端优先训练什么？

- **结论**：先 lifecycle/owner/异步、权威状态与协议、内容/版本影响、因果调试与目标设备验证，再按任务补架构。
- **证据**：C1/C2 固定源码揭示这些交界风险；具体优先级是本研究建议，不是行业人群统计。
- **边界**：渲染/工具链/平台等岗位应调整顺序；不能只学 UI 异步而忽略业务。
- **行动**：一条真实功能纵线、一个多因 bug、一个真机 profile、一次 AI 验收，按风险轮换。

### Q12 能否建立通用而不重流程的个人方法？

- **结论**：可以先用“任务卡—证据—条件规则”的可裁剪协议；通用的是提问结构，不是固定答案/文档量。
- **证据**：本包 Tier/模板/场景为设计产物，尚未证明长期收益。
- **边界**：不同团队需对齐正式流程；个人模板不替代授权/安全/发布门禁。
- **行动**：低风险只四问，每周复查哪些记录真的改过决定，保留有用字段并用真实结果评估。

## 11. 局限、反证与后续研究

### 仍未满足的关键要求

- 六个充分一手真实案例：目前只有 C1/C2 静态材料足够，C3–C6 待补。
- 认知/学习、标准正文与软件工程直接研究的方法/样本/限制核验：未完成。
- 七模型实际有效性与训练因果：没有数据；C1/C2 只是局部可解释性/适配检查。
- Unity 编译/测试/目标设备测量、历史修复独立回归：全部未做。
- 真人学习评价、人工技术审核、发布批准：未做。AI 审查不能替代。

### 可以推翻或收缩本模型的结果

1. 控制熟悉性/领域知识后，候选跨任务操作不再贡献，应缩小“通用判断”主张。
2. 文档更完整但预测/错误发现/迁移无改善，说明流程主要改表达，不证明能力。
3. 更慢且不降高后果错误，需删减流程；更快但漏关键风险，不算收益。
4. 规则只在原案例有效，变式失败，需补边界而非怪学习者不努力。
5. AI 工作流提升当下产出但无辅助表现下降，需要重新分配探索/生成；反之也应保留收益，不能先定立场。

### 有限恢复顺序

优先补 cog-05/06 软件理解/信息需求正文；补 C3/C4 一个具体源码故障链、C5 固定 KEP 与实现/里程碑、C6 真实 ref/论文/harness；补 METR 2025 与安全/技能形成的不同方向原始材料。访问恢复或合法材料可得时定点继续，不重复全网检索，不绕过拒绝，不访问公司私有工程。

训练评估先做小规模可审计试用：固定任务/评分/基线、记录提示与熟悉性、即时/延迟/近远迁移、盲评一致性与成本。无对照只描述观察；若要识别某训练成分的因果，需进一步设计而非多指标后选最好结果。
