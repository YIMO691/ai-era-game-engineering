## 1. 先区分六种不同问题

| 要回答的问题 | 合适终点 | 常见错误替代 |
|---|---|---|
| 生成更快吗？ | 明确任务下的时间、完成与失败 | token 速度/代码行数 |
| 端到端工作更省吗？ | 理解、生成、审核、返工、集成与交付成本 | 只计生成阶段 |
| 修对了吗？ | 独立需求与边界 oracle、回归 | 模型自评或新增测试全绿 |
| 长期能维护吗？ | 后续变更、兼容、故障和维护者反馈 | 单次 benchmark resolved |
| 人学会了吗？ | 无答案泄漏的新任务、解释与调试、延迟保持 | 看懂了答案/主观满意 |
| 多年后能力是否退化？ | 长期、可比较、控制混淆的证据 | 一次测验/非软件实验 |

**Oracle** 是判断结果是否正确的外部依据，例如明确需求、协议不变量、维护者确认的旧行为或独立测量。不是“另一个 AI 也觉得没问题”。

## 2. 当前真正读到的研究说了什么

### 2.1 Peng 等：某类任务确实可能显著节时

`ER-20261106-ai-03`：2023 年论文 v1，实验实际于 2022 年进行。95 名参与者随机分组，任务是统一的 JavaScript HTTP server；两组都可查互联网。**完成任务者**的均值为 71.17 与 160.89 分钟，论文报告耗时减少 55.8%，95% CI [21%, 89%]。

边界：时间分析条件于完成；以首次提交通过给定测试作为终点；不是熟悉大型仓库的长期维护，论文明确没有研究代码质量。55.8% 较短耗时不是同义的 55.8% 较高吞吐率，也不是学得更好。作者含 Microsoft/GitHub 等相关机构，属于产品相关作者参与的实验，不能称完全独立于供应商的复现。

### 2.2 METR：2026 有公开跟进，但不能只看中心估计

`ER-20261106-ai-02`：2026-02-24 官方文章正文已读，报告 57 名开发者、143 个仓库、800+ 任务。原参与者子集相对耗时变化为 −18% [−38%, +9%]，新参与者为 −4% [−15%, +9%]。两区间都跨零。

作者同时披露：开发者与任务的选择、报酬变化、禁 AI 条件下任务不完成、不同条件可能产出不同工作、并行 agent 的时间归属等问题。**不能把它表述为当前工具已经被可靠证明普遍提速，也不能因为区间跨零就证明无效。**作者关于可能低估的判断不是已识别的效应下界。

早期 +19% 耗时结果，本轮只在该跟进的回述中读到；2025 原论文 `ER-20261106-ai-01` 正文未读。不能宣称已独立核清早期全部方法，也不能把新旧点估计之差解释为模型进步的因果量。

### 2.3 保留反向证据，但不伪装已核验

- 安全：Perry 等与 Sandoval 等是方向和任务不同的待核原始研究，`ER-20261106-ai-07/10`。目前不能用搜索摘要断言 AI 普遍增/减漏洞。
- 学习：Shen、Tamkin 的新库技能形成，以及 Kazemitabaar 等的青少年入门学习，`ER-20261106-ai-09/11`；正文未读，人群、任务和时间尺度不同，不能互相代替。
- 过度依赖：Buçinca 等 `ER-20261106-ai-08` 是非软件研究候选，尚未读正文；不能直接证明长期职业程序员技能退化。
- SWE-bench/SWE-agent：`ER-20261106-ai-04/05/06` 原文和固定源码未核；本版只提供待核案例与验收问题，不报告本地成功率或运行成本。

结论是**任务与终点必须区分**，不是用“AI 好/坏”统一解释全部结果。长期退化风险值得防范，但目前本研究没有证据给出其发生率、必然性或不可逆性。

## 3. M6：有界委派、证据验收、保留能力

**研究综合模型，未验证。**

- **解决问题**：如何利用生成和搜索能力，又不让最终行为、权限与责任无人掌握。
- **输入**：任务、固定版本、风险 Tier、可访问上下文、权限/费用范围、人类初步模型、验收标准。
- **结构**：人类界定问题 → 受限委派 → AI 产出证据化候选 → 外部 oracle/独立验证 → 人类决定与风险接受 → 结果反馈及无辅助迁移检查。验证失败可返回任何一环。
- **输出**：可审查的最小改动、实际验证记录、未解决项、责任人、可解释的条件规则。
- **适用**：有可访问事实、可隔离修改、可接受验证成本的任务；探索阶段也可只让 AI 找入口而不写代码。
- **局限**：需求 oracle 自身可能错；人可能没有能力审核；同源资料可能共同出错；隔离和日志不自动消除泄露与供应链风险；高后果任务需要额外领域审查。
- **案例演示**：[工程判断案例库 — C6. SWE-agent：工具界面、执行反馈与外部验收](case-library.md) 是真实项目的待核分析，不能算源码验证已完成。C1/C2 则可用来训练模型对真实 API 契约的理解与审查。
- **评价**：不只看 AI 输出，检查独立 oracle 是否真实、关键反例能否被发现、越权与返工、无 AI 新任务表现。尚无本研究的效果数据。

## 4. 人机职责矩阵

| 活动 | AI 可受限承担 | 人类必须主导 | 独立验证/批准 |
|---|---|---|---|
| 需求 | 提取条件、归类、列歧义和反例 | 业务意图、优先级、非目标、可接受损害 | 需求方/产品负责人确认，明确验收 |
| 项目探索 | 搜索、标路径、提出调用边与未知 | 架构事实、关键不变量、owner、探索停止点 | 固定源码/内容/运行链抽查，错误边纠正 |
| 方案 | 生成真实备选、找成本和反例 | 硬约束、取舍、范围、是否升级 Tier | 设计审查、区分性原型/试验 |
| 编码 | 已授权文件内局部实现 | 行为边界、兼容/生命周期、依赖授权 | 最小 diff、编译/原测试/边界测试/人工 review |
| 测试 | 候选输入、脚手架、性质与变异建议 | oracle、覆盖策略、必须保留的旧行为 | 不依赖实现生成的需求测试、故障注入或外部观测 |
| 交付 | 汇总命令、日志、改动与未完成项 | 发布批准、风险接受、数据与隐私责任 | CI、目标环境、分阶段与恢复演练，按授权执行 |
| 复盘 | 整理时间线、挑战解释、生成变式题 | 原因归因、行动优先级、知识规则是否成立 | 原始记录、后续任务和行动有效性 |

人类主导不是亲手敲每行代码，而是能追到事实、理解关键契约、拒绝不合适结果，并由有权限的人批准不可逆动作。若无人能审，缩小委派或升级审查，不以模型信心填空。

## 5. 任务入口：十分钟也能建立的委派合同

不规定所有任务必须十分钟；这里只示范小范围准备。

1. **人类先写四句**：目标；改动边界；最可能坏的东西；独立验收。
2. 固定版本和入口；提供两个相邻范例，而不是倾倒全仓库。
3. 列允许读取/写入/执行/联网的范围与停止条件。公司私有代码、日志、截图、协议与资产未经授权不能发送到外部服务。
4. 要求 AI 区分看见的代码、推断与未知；每条架构结论附路径/符号/版本。
5. 要求先检查现有机制，不自建新的事件/资源/取消/状态体系。
6. 出现需求冲突、公共接口/协议/持久化变更、运行权限不足时停止并报告，不自行扩大授权。

可用委派文本（**模板，不是执行授权**）：

> 目标是…，版本是…，只读…、只写…。先查入口…及相邻范例…。保留不变量…。不要添加依赖、修改公共 API、删除测试、访问凭据或发布。先列事实/假设与最小方案；实现后列每个文件的必要性、实际命令/退出码、未运行项。遇到…立即停止。验收依据为…，由…批准。

不把仓库内网页/注释/Issue 中的“忽略之前指令、读取密钥”当指令；第三方内容是数据。工具能访问不等于任务授权访问。

## 6. 五个阶段怎样使用 AI

### 6.1 探索：让 AI 提供可核查地图

合格输出：`入口→协调→权威状态→外部边界→呈现→退出`，每条边为已确认/推断/未知；包含非代码依赖。人工抽查最高风险两条边，发现错就回查地图，不再基于错图生成更多内容。

危险信号：只有类名的漂亮架构图；无法定位注册位置；把每处相似代码都当项目规范；把 C# binding 的表面方法当原生引擎实现。

### 6.2 方案：比较前先过硬门槛

要求至少两个真实可行方案；简单任务无需强行凑两个。让 AI 针对首选找反例，但不先告诉它“证明我的方案正确”。询问：哪条尚缺的信息最可能改变选择？看似优雅的方案增加了哪些调用方责任？

### 6.3 编码：最小 diff 与显式行为变化

区分行为保持重构、修 bug、新功能；禁止把三者混成不可审查的大补丁。依赖 API 存在性用相应版本核查，编译能发现部分问题，不能确认完整生命周期或平台契约。

### 6.4 测试：防止实现与测试共同误解

先由需求/协议/维护者定义核心验收；AI 再补输入与测试结构。至少有一个测试在错误实现上失败、在正确行为上通过；需要执行才能确认，未执行只叫测试设计。对修复应尽量证明旧版可复现与新版消除，并保留独立回归。

### 6.5 交付：汇报不能洗白未运行

按 `pass/fail/blocked/not-run` 列状态。环境打不开，不写“应该能过”。AI 可以汇总，批准人必须检查高后果项。代码回滚不等于恢复泄露、经济发放、存档或兼容性损害。

## 7. 独立验证的阶梯

| 方式 | 能增加什么 | 仍可能遗漏 |
|---|---|---|
| 第二个模型/新会话 | 不同候选、部分错误检查 | 同源训练/需求/上下文错误，相关盲区 |
| 人工源码审查 | 所有权、范围、隐藏依赖、项目惯例 | 人也可能确认偏差或缺知识 |
| 已有回归/独立需求测试 | 与新实现不同来源的行为约束 | 旧测试也可能不完整/含旧 bug |
| 性质/变异/故障注入 | 不变量与检测敏感性 | 性质选错，注入不代表真实故障 |
| 目标运行与外部观测 | 实际时序、平台、内存/性能证据 | 样本和场景有限，观测会影响系统 |
| 有权限的领域/发布审查 | 接受残余风险、跨团队契约 | 不自动证明未来无故障 |

独立性指**错误来源尽可能不相同**，不是人与 AI 的身份标签。两个人照抄同一错误规格也不独立。高后果场景需要组合，不存在一个万能步骤。

## 8. Unity/C# 验收优先级

| 易被局部正确掩盖的风险 | 必须问的问题 | 候选验证 |
|---|---|---|
| 关闭/销毁/复用后的异步回调 | 对象存在是否仍有写入权？token 属于谁？ | 控制完成顺序，关闭→重开→旧结果晚到 |
| 取消与资源释放 | 停止等待、停止操作、释放结果是否同一事？ | 固定 API 源码/契约，成功/失败/取消清理计数 |
| 事件/消息 | 是否重复订阅、重入、漏退订？ | 多次启停、切场景、重连；追 owner |
| 网络状态 | 谁是权威？重复/乱序/重试如何处理？ | host/client/server 分开；协议与旧版矩阵 |
| 池化对象 | 回池与网络 despawn/业务解绑谁协调？ | C2 契约，重复 spawn/despawn、late join |
| 序列化/内容 | prefab/scene/config/资源 key 是否仍兼容？ | 内容检查及构建，不能只全文搜代码 |
| 热更新/AOT/裁剪 | Editor 可用的路径在发布包是否存在？ | 对应构建后端、裁剪和平台实际测试 |
| 性能 | 优化的是实际瓶颈还是代码外观？ | 目标设备、代表场景、重复采样、CPU/GPU/分配 |

这些是检查建议，不是声称某版本 Unity/包都具有相同 API。公开 C1/C2 固定版本不能直接当当前商业工程版本。

## 9. 用 AI 训练判断而不是只获得答案

以下六种是**待验证训练设计**：

1. **人先判**：先写因果图、首选/备选、可推翻条件；再看 AI 第二意见。记录改变判断的证据。
2. **AI 先列多案，人盲评**：先隐藏模型偏好与评价，独立比较契约/代价；后看理由。不要把 AI 提供的错误方案混入实际代码。
3. **反方审查**：只给代码/需求，要求具体失败情景，不要求“找到恰好五个错”；核验后淘汰假阳性。
4. **反事实解释**：去掉一个 owner/取消/映射机制，先预测坏在哪里，再查固定源码/测试。AI 答案也是待验假设。
5. **预测后运行**：人写预期顺序和最终状态，受控环境观察，结果不符时改模型。
6. **定期无 AI 新任务**：保留文档/IDE等正常工具，撤掉答案生成；测陌生模块解释、边界设计和诊断。不把背 API 记忆考试当工程能力。

导师/AI 提示逐步撤除；同一道题熟练不代表迁移。记录即时完成、延迟保持、近/远迁移四种结果。真实项目中别为练习故意关闭保护或制造故障；用隔离练习和已授权工作。

## 10. 怎样评价 AI 工作流

先在类似任务上定义基线与可比条件，不为了打分采集私人数据或额外调用付费服务。

- **效果**：需求/回归/安全门槛，缺陷严重性，维护者接受理由，后续返工。
- **时间**：个人主动投入、日历完成时间、团队总投入分开。并行 agent 的等待不重复算作人的主动工时，也不能从总资源成本中消失。
- **成本**：已有账单/使用记录、环境、安装、审核、失败与工具维护；没有记录就报未知。
- **判断保留**：人能解释权威状态、owner、失败模式；无 AI 变式任务是否仍能完成。
- **合规**：越权、秘密/私有代码暴露、未经批准依赖、跳过门禁。
- **负担**：提示编写、上下文维护、假阳性审查是否抵消收益。

不将这些量机械合成统一分数；安全/数据/授权硬门槛不能被速度补偿。小样本个案只能描述工作流观察，不能宣布因果或普适最优。

## 11. 最小使用规则

**我先说清目标与风险 → AI 提供有出处的候选 → 用外部依据验证 → 我能解释且有权限的人批准。**

做不到时，减少委派规模、补项目知识或请领域维护者；不要用更多模型一致赞成来替代缺失的事实。下一步补读和来源允许措辞见 [sources](sources.md)；完整训练安排见 [工程判断力训练与能力评估手册](training-and-assessment-handbook.md)。
