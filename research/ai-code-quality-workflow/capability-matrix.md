# 能力与候选矩阵

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

这是固定源码的**机制比较**，不是运行排名、效果评分或兼容认证。来源ID统一见[来源登记](sources.md)；版本/许可/读取范围在那里及四份evidence附录。所有候选均未在本机安装或执行，Unity版本未知；F1/F2记录宿主文档访问缺口。矩阵先区分能力责任，再决定是否引入包。

## 十二项能力：什么负责，什么不能证明

“提示”=模型的自然语言任务；“程序”=已读实现中的确定规则；“服务”=外部审查后端；均不自动成为当前工程中的已生效门禁。

| 能力 | 已找到的承载物 | 证据类型 | 核心缺口与本题取舍 |
|---|---|---|---|
| 1. 理解任务与非目标 | feature-dev发现/澄清；ECC development-workflow | 提示 O1/E1 | 不能替用户决定行为；复用简短任务卡即可 |
| 2. 追踪仓库架构 | feature-dev code-explorer、architect | 提示 O1 | 要入口→调用链→状态/副作用→关键文件；目录树不够。小修单主线程先读 |
| 3. 约束与按需知识加载 | CLAUDE引用、Skills渐进加载 | 提示/组织 O1/O2 | F1未核验全部自动发现语义；先显式读路径、回述约束 |
| 4. 最小实现 | feature-dev人工闸门、ECC开发流程 | 提示 O1/E1 | 无最小diff证明；由范围声明和最终diff核对承担 |
| 5. 简化与重构 | code-simplifier、toolkit同名角色、ECC refactor-cleaner | 提示 O1/E1 | 原定义有JS偏置/主动修改；仅按需提案，修改后重验证 |
| 6. 缺陷审查与误报核验 | code-review、toolkit代码角色、CodeRabbit | 提示/服务 O1/R1 | 自评≠证据；官方command的state过滤不适合覆盖Unity生命周期，逐项验证 |
| 7. 测试设计与TDD | toolkit测试角色、ECC tdd-guide、skill-creator断言思路 | 提示 O1/E1/O2 | 建议测试不等于执行；不强制80%/100%覆盖，保留红→绿→回归记录 |
| 8. 确定性编译/分析/格式 | Unity分析器、StyleCop、Roslynator；现有编译器/格式工具 | 程序 U1/S1/A1 | 宿主、版本、规则集先核验；EditorConfig只是配置、不是执行器 |
| 9. 架构依赖约束 | NetArchTest；项目已有asmdef边界可优先检查 | 程序 N1；asmdef检查是提案 | 方向、程序集、非空、负例需明确；资产引用/运行行为不在一般类型依赖覆盖内 |
| 10. 错误/注释/类型专项 | toolkit三类角色、ECC C# reviewer | 提示 O1/E1 | Sentry/.NET惯例不直接套Unity；按风险选一项，不全套评分 |
| 11. 反馈、评估、规则淘汰 | skill-creator baseline/盲比较；ECC hooks | 提示+脚本 O2/E1 | 触发评估≠代码质量；aggregate单位/分组有陷阱；反馈先人工证据，不自动长规则 |
| 12. 权限、终态、恢复与成本 | CLI scope；OpenHands事件/终态；CodeRabbit授权边界 | 宿主帮助/程序/服务 C1/H1/H2/R1 | 临时加载≠沙箱；事件恢复≠副作用幂等；结束/零发现≠完成验证 |

## 候选逐项采用矩阵

标签：“先复用”不等于已安装；“试点”需要另行批准且只在授权沙盒；“借鉴”不复制整包；“暂缓”不等于工具无价值。

| 候选 | 最值得保留的机制 | 依赖/成本/风险 | Unity/C#处理 | 当前决定 |
|---|---|---|---|---|
| 官方 code-simplifier | 最近变更范围、清晰优先、行为保持目标 | 主动修改；无等价保证；模型调用成本 | 去除React/ES modules等偏置；保留资产/生命周期契约 | 借鉴；不默认自动运行 O1 |
| 官方 code-review | diff审查、逐项复核、评论闸门 | 前置+多审阅+逐项agent，不止4次；不跑linter；README与command漂移 | 必须补状态/生命周期审查，不照搬输入/state排除 | 非首选默认；PR场景有条件试点 O1 |
| 官方 pr-review-toolkit | 按代码/测试/注释/错误/类型/简化分风险选角色 | 自评分不校准；部分角色修改；错误规则依赖Web约定 | 优先测试/代码阅读思想；只读角色明确禁写，去Sentry偏置 | 最值得单项试验的官方审查候选 O1 |
| 官方 feature-dev | 追踪调用链、主线程亲读、实现前获批 | 完整流程7–9子agent调用；工具名映射未验证 | 大功能探索可借鉴；小修用单线程任务简报 | 先复用流程，不默认全套 O1 |
| anthropics/skills | 渐进加载、baseline/断言/人工反馈 | 不统一许可；skill-creator写临时commands/启动claude；Windows未测 | 旧指南按需引用，先不创建专用Skill | 借鉴组织；按重复摩擦再决定 O2 |
| ECC | 规则分层、开发/TDD/清理思路，实际C#角色 | Node/hooks/安装链；quality-gate无.cs且非阻断；自动format | 不套ConfigureAwait(false)、50行、80%等硬指标 | 局部借鉴，不整套安装 E1 |
| OpenHands Canvas+SDK | action/observation、终态检查、恢复边界 | 新平台/服务/依赖；命令副作用/预算；review实现在第三仓 | 本题没有Unity适配证明；不替换现有CLI | 不采用平台，只借鉴 H1/H2 |
| CodeRabbit skills | 结构化审查事件、逐项批准/最小修复 | CLI/认证/云端外发/额度；整文件staging隔离缺口 | 不提供Unity完整性保证；需数据政策/合同批准 | 暂缓外部服务 R1 |
| Microsoft.Unity.Analyzers | Unity语义诊断、序列化字段抑制 | 可能IDE已有；加载/版本/CodeFix意图需验 | 优先盘点，按规则与正反例核验；不是全部Unity资产可达性分析 | 确定性工具第一候选 U1 |
| StyleCopAnalyzers | 团队语法/组织一致性 | 规则迁移噪声；最新列出beta；shipping pin缺口 | 选少量约定，风格不冒充缺陷，不全设Error | 团队已有一致需求再选 S1 |
| Roslynator | 丰富诊断/重构、部分Unity回调保护 | 变体/配置/IDE与编译宿主差异；删除式修复 | 禁无人值守unused删除/Fix All，逐条验资产/反射入口 | 白名单诊断试点候选 A1 |
| NetArchTest | 指定类型到namespace依赖方向断言 | 旧release/HEAD、Cecil非公开API、空集假通过 | 纯C#程序集先试；不替代scene/prefab/asmdef实际验证 | 有硬边界需求才保留 N1 |

## 原生能力、插件与确定性门禁不互相替代

| 问题 | 现有Claude Code可承担 | 仍需外部证据/人 |
|---|---|---|
| 编码前是否理解 | 阅读任务相关关键文件、回述owner/入口/状态、提出疑问 | 业务意图、未读资产、隐含历史由负责人确认 |
| 编码是否保持行为 | 最小diff、局部自检、提出反例 | 编译/行为测试/资产与设备结果；AI自称等价不算 |
| Review是否可信 | 另一个只读上下文提出“输入/状态→路径→后果” | 运行或人工核对；新agent仍是AI，不是独立效果实证 |
| 门禁是否阻断 | 展示命令、保存结果、失败后停止提交建议 | 宿主/CI必须传播非零、检查报告新鲜性与覆盖；本题不部署 |
| 是否更快更优雅 | 给改动理由和备选方案 | 同任务对照、人工修改任务、目标设备性能测量 |

## 比较后形成的最小组合

建议而非实测最优：**现有Claude Code + 一份短项目契约/任务卡 + 旧材料按需读取 + 已有编译/测试/格式与Unity分析器盘点 + 风险定向只读审查 + 一份反馈记录**。不需要新Agent runtime、数据库、Hook或专用Skill。候选都不是这一组合的强制安装项。

详见[采用方案](adoption-plan.md)；八问与证据推理见[研究报告](research-report.md)。没有单项工具能覆盖十二项，也没有本轮数据支持“多个Agent一定更好”。
