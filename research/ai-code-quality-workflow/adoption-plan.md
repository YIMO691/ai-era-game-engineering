# 最小采用方案

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

## 决策摘要

**推荐从零新增依赖开始，而不是从安装清单开始。** 保留现有Claude Code；把项目约束、按需知识、已有确定性检查和风险审查连接起来。本文是待批准的实施设计，未创建项目配置、安装插件或修改业务工程。

依据：[十二项能力比较](capability-matrix.md)与[B1/O1/O2/C1/E1/H1/H2/R1/U1/S1/A1/N1](sources.md)。最小方案是低维护判断，不是实测最优。F1/F2的完整宿主/Unity兼容缺口未关闭，旧题人工pending与示例未运行的限制仍生效。

## 1. 常规任务的最小组合

| 组成 | 最小职责 | 不承担的保证 |
|---|---|---|
| 现有Claude Code主线程 | 读任务文件、追调用链、最小实现、报告证据 | 不因读过指南就必然遵守，不替编译/人工 |
| 一份短项目契约 | 入口/模块边界/不可改事项/验证入口/停止条件 | 不是权限系统或OS沙箱 |
| 每任务一张简报 | 目标、非目标、owner、允许范围、验收与未知项 | 不写成长期重复规范 |
| 旧材料按需链接 | 针对当前风险选择指南/案例/清单 | 不把11个未运行例当标准库/测试夹具 |
| 已有验证链 | 格式/编译/分析/测试/必要Unity与设备检查 | 不将一层通过外推到所有平台 |
| 定向只读Review | 对一个主要风险给可核验发现；作者逐项处理 | AI角色分离不是独立效果实证 |
| 一份反馈记录 | 保存确认问题、规则变更与删除理由 | 不自动提炼所有意见，不承诺后台学习 |

小修可以由单主线程完成探索、自检和验证；是否另开审阅角色取决于风险，不按文件数量机械决定。涉及生命周期、跨模块协议、序列化迁移、资源/线程交接时，增加定向审查的理由更充分；不默认多Agent。

## 2. 采用层次

### A. 优先复用，仍须确认工程授权

- 任务前真实调用链简报，借鉴feature-dev而不必安装整套。
- 旧Review三类输出与逐项核验。
- 已有编译/测试/分析器；先盘点，不新增包覆盖已存在配置。
- 每次报告命令/退出码/未运行项，修复后重新验证。

以上也不自动授权读业务工程；未来必须先指定可访问的项目和目录。本轮只写研究文档。

### B. 有明确收益假设时，单项试点

1. **Microsoft.Unity.Analyzers**：先查IDE/编译宿主已经加载什么，再在授权副本验证少量规则，确认正例、反例和重复诊断。不能仅凭netstandard或Roslyn数字断言兼容。
2. **pr-review-toolkit单一只读方面**：优先代码或测试角色的审查思路；明确禁写、禁提交/评论，去除Web偏置；先比较不安装时的等价任务提示。若原定义/宿主不能维持范围，就只借鉴提示思想而不加载包。
3. **Roslynator白名单诊断**：需宿主实测与Unity例外；不启用删除式自动修复。StyleCop仅有团队约定时试少量规则。
4. **NetArchTest**：已有明确程序集依赖禁令但现有检查不足时才评估，维护陈旧须能接受。显式程序集、非空/marker、负例缺一不可。

### C. 本轮不引入

- 专用`client-code-quality` Skill：当前无复用能力不足的证据。
- 全套ECC/Hooks：.cs覆盖和阻断语义不满足所需，安装链/全局副作用未审完。
- OpenHands平台：不是当前质量问题所必需。
- CodeRabbit服务：代码外发/合同/额度未获批准。
- 自动Simplifier、自动Fix All、每次编辑多Agent扇出。

## 3. 分阶段实施与验收

| 阶段 | 行动 | 可验收证据 | 停止/撤回条件 |
|---|---|---|---|
| P0 授权盘点 | 明确沙盒、可读写目录、预算、允许模型处理的材料与服务/部署方式；批准后读配置和版本 | 目录及模型通道授权、现有文件hash、版本/已加载规则清单 | 通道未知、要求全本地但环境未证、全局修改或私人目录则停止该步 |
| P1 零新增基线 | 用现有能力执行少量代表任务，保留简报/diff/检查/人工结果 | 原始命令、时间、任务覆盖、人工确认缺陷/返工 | 任务无法隔离/无验收则先补契约，不急装插件 |
| P2 补确定性短板 | 仅选择一个缺口：例如Unity分析器规则或回归测试 | 正/反例、宿主版本、非零传播、报告新鲜性 | 无法加载、诊断重复/噪声或不理解规则则撤回 |
| P3 单项审查对照 | 一次只改变一个因素：增加定向角色或插件 | 同任务起点/预算/最终diff/人工判断与成本 | 无收益、误报返工、扩大范围则不采用 |
| P4 固化与删减 | 只固化稳定有用规则，记录owner/例外/淘汰条件 | 可追溯的规则变更与对应失败证据 | 规则无效/过时/重复则删除或改为按需资料 |

没有阶段必须安装插件。每阶段可以得出“现有组合足够”并停止。后续实践不在本轮自动执行。

模型处理通道也属于数据边界：使用远端模型时，读取源码可能将内容送入模型上下文。禁止新增第三方审查服务，不等于所有代码都留在本机。必须明确允许发送的材料和目标服务/部署方式；若要求任何代码不出本机，先验证合适环境，未确认前不读新源码。

## 4. 小范围验证设计（未运行）

建议选择四类**非生产、授权**任务：纯C#行为小修；启用/停用期事件；异步迟到结果与资源交接；一个已明确程序集依赖禁令。来源可以是经人工确认的原创夹具；旧例仅作设计启发，需先补成可编译测试，不复制生产代码。

- A组：现有Claude Code＋同样项目契约/任务资料/确定性工具。
- B组：在A基础上只加一项候选审查/规则。若比较Skill，不同时换模型、测试集和Agent数。
- 使用独立初始快照和同等任务描述，记录模型/版本/设置/预算；顺序尽量平衡，避免把前一轮答案泄给后一轮。样本很小只能作筛选，不推行业统计。
- 程序验证：预先指定行为断言、失败场景、测试集合与报告新鲜性；计入无法执行/skipped。可以预置已知故障用于召回检查，但不能用AI新发现数代替真实缺陷数。
- 人工验证：不看组名地做指定阅读/修改任务，记录理解错误、返工、契约违背、无关diff、审查误报；允许“无差异/更差”。没有真实人工就标缺失。
- 成本：实际墙钟、模型调用/可取得的真实token或费用、人工时间。字符数不能填token，估算单独标注；不预报百分比提升。
- 性能任务另行设计：固定设备、构建、场景、基线、重复测量与噪声分析。源码new/LINQ推断只形成待测假设。

试点可预先约定最多一次实现修正与一次复核；仍有未解决硬契约缺陷则停止人工处理，不无限“修到零发现”。这是可更改的试验上限，不是成熟工具实际内置限制。

## 5. 权限、撤回与维护成本

- 只在授权沙盒和项目范围动文件；先读取目标与Git状态/hash，保留已有未提交改动。不要求用户为工具先提交所有内容。
- 对可能带Hook/命令执行的插件，检查固定版本定义、依赖、网络与工具名冲突；临时`--plugin-dir`不是沙箱。任何新服务、收费调用或权限扩大另批。
- C1帮助证明install和marketplace add默认user，且install `--marketplace`可能先写user settings。禁止用省事命令违反不改全局约束；本题没有实施安装处方。
- 撤回只恢复本次明确拥有的配置/依赖/diff；先看当前内容，若用户已改不直接覆盖。不用`reset --hard`、目录清空或全局卸载。
- 若只临时会话加载插件，结束该会话只能停止继续加载，不能撤销其写过的文件、外发、提交或外部动作。外部服务的数据不能假定可撤回。
- 维护不建平台：一个项目契约、一份按需指南入口、现有CI/测试入口、一份反馈记录足够。无自动同步全局、调度、数据库或面板。

## 6. 成功与失败的定义

文档方案成功：读者能在不扩大权限的情况下找到下一项可核验行动。采用试点成功：在指定任务/预算下，程序与人工证据支持保留某项能力，且范围/噪声/维护成本可接受。两者不同。

出现“检查没跑、报告旧、选择集空、服务skipped、退出但终态error、AI只说通过”时，结论是**未验证或失败**，不是合并/发布许可。用户人工审核研究版本也不自动批准代码外发、安装或修改工程。
