# Unity与C#适配

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

这里不是第二套代码质量指南，而是把旧题B1接到**输入契约、检查器和验证环境**。引用ID见[sources](sources.md)。实际Unity/UTF/API profile/后端/平台未知，F2文档正文访问失败；下文是待验证协议与风险清单，不是某版本Unity的安装/命令处方。所有候选分析器、案例、测试设计均未在Unity运行。

## 1. 先补环境事实，不从本机.NET推断

后续只在获批沙盒读取：Unity精确版本、UTF包、C#与API兼容级别、Editor/Player后端和目标平台、asmdef及条件编译、IDE/扩展与实际加载的analyzer版本、已有格式/诊断/测试配置、现有CI入口。不要读取凭据或无关项目。

本机.NET SDK版本只能说明本机安装了什么，不能证明Unity可加载某Roslyn DLL、支持record/语法或Player API。分析器的netstandard目标、开发工具链与其被分析游戏的运行时是三个层次；U1开发要求.NET10不等于玩家要求.NET10。IDE看到诊断也不证明Unity编译/CI加载同一版本。

## 2. 把商业客户端风险映射到证据

| 风险 | 编码前必须问 | AI审查任务 | 程序/运行验证责任 |
|---|---|---|---|
| 序列化与资产入口 | 字段名/类型、引用来源、scene/prefab/UnityEvent或反射入口？ | 不因私有/未调用就删或改名；明确迁移影响 | 授权资产检查、导入/重载、绑定/场景回归；C#编译不足 |
| Unity对象存活 | owner是谁，何时失效，当前null判断语义？ | 区分托管引用与Unity对象有效性，追销毁后路径 | 针对用户版本的销毁/访问用例；不泛化所有`?.`改写 |
| 启用/停用事件 | 订阅属于启用期、存活期还是服务期？publisher可否替换？ | 同一回调订退、重复启用、Bind时序、重入/异常前提 | PlayMode行为计数、旧publisher不再触发；必要场景切换 |
| 异步迟到结果 | 取消是否只停等待？请求新旧如何判？谁释放迟到资源？ | 分开取消/有效性/接管/释放/线程，沿异常路径核对 | 可控完成顺序/取消/异常夹具，所有权计数；实际平台再验 |
| 主线程与Player | continuation/Dispose在哪个线程，依赖何种宿主？ | 不机械套ConfigureAwait(false)，不以Task返回保证线程 | 目标环境线程/时序断言，Player/IL2CPP条件验证 |
| 热路径性能 | 真实热点、帧预算与目标设备是什么？ | 源码只列分配/调用假设，不给改善百分比 | Profiler/设备构建、基线/重复数据与场景一致性 |
| 模块依赖 | 哪个source程序集禁止依赖哪个target，例外是什么？ | 不凭目录自动推导层次，读asmdef与关键类型 | 编译边界/显式架构断言＋非空/marker/负例；资产另查 |
| 错误与取消 | 正常取消、可恢复失败、最终报告层在哪？ | 不把无本地日志一律判critical；不重复吞错/报错 | 错误路径与可观测结果测试，校验上层报告约定 |

这些风险由旧指南/案例引出，不是每个项目都必须采用同一实现。输入未知就不能自动改代码“符合规范”。

## 3. 一个贯穿例：UI在结果回来前停用

**教学推演，非已运行案例。** 面板启用后订阅分数并发起异步加载；用户切换界面，面板停用；旧请求随后成功，新面板或新请求已经出现。

### 编码前简报应包含

- 订阅有效期由业务决定。本例假设只在启用期间接收事件，停用后必须解绑；不是所有对象都应如此。
- publisher是普通C#对象还是Unity对象？是否可在启用时替换？访问器会不会重入或抛异常？这些会影响旧题T5示意的适用性。
- “取消等待”不保证producer停止。旧结果若携带资源，谁接收并释放？新旧请求怎样比较？结果接管是否会回调/部分失败？
- 结果应用与释放要求哪个线程？Disable、Destroy、重启请求的次序可否交错？读实际实现，不靠方法名猜。

### 应先设计的验证场景

| 场景 | 可观察断言（依业务确认） | 层次 |
|---|---|---|
| 启用→停用→再启用，多次重复 | 每个启用期订阅一次；停用期无Refresh | 可控publisher纯逻辑测试＋实际PlayMode生命周期 |
| 启用时替换publisher | 旧source不再触发，新source仅触发一次 | Bind/订退回归；实际Unity对象另验有效性 |
| A先发、B后发，B先完成 | 只有当前请求影响UI，A成功结果被正确释放 | 可控异步夹具，不靠随意延迟“碰运气” |
| owner失效后producer仍成功 | 不应用旧结果；未接管资源恰当释放 | 所有权计数/线程断言；不能只检查没抛异常 |
| producer失败或接管失败 | 失败契约可观测，释放责任无空洞/重复 | 异常路径；部分接管规则须预先定义 |
| producer永不完成 | 不承诺finally必运行或资源问题自动解决 | 单独定义超时/后台任务/producer责任 |

旧题T6的`pending→Adopt→pending=null→finally Dispose`只在接管原子性、结果非null、线程等前提下有意义；取消令牌本身不能替代有效性代次。这里不复制示意为生产API，也不声称已有完整可编译夹具。

### Review如何避免两个相反错误

- 不采用官方code-review O1“依赖特定state就不报”的过滤来覆盖此题。这里的失效状态就是明确验收条件，需要按路径核对。
- 不让Simplifier为了短小把订退、有效期与接管合并成一个抽象或删除“看似重复”的边界检查；也不能因为存在状态字段就认定设计差。
- 发现必须绑定已确认契约。若产品要求停用后仍后台刷新数据，不能把所有停用期更新一律判bug；区分UI访问和数据服务。

## 4. 确定性工具怎么接，而非装什么就算完成

### Unity分析器 U1

优先确认是否随IDE已有，记录版本/宿主和诊断ID。UNT0012实际只覆盖直接expression statement、MonoBehaviour派生类型方法和IEnumerator返回；它不能知道本次丢弃是否有意、调用是否有立即副作用。包StartCoroutine是候选修复，不是业务证明。serialized suppressor的范围有限，不能由它推导任意资产已绑定或全部私有成员安全。

试点至少一个该规则应报的正例、一个不应报/不应修的反例，以及Editor/CI诊断一致性。先选择规则再讨论严重性；修复始终看diff与行为回归，不默认BatchFixer全跑。

### EditorConfig、StyleCop S1、Roslynator A1

EditorConfig是配置载体，不是执行器。先找工程现有格式器/analyzer如何解释它，确认哪些规则真在IDE、编译和CI执行；不要新建`root=true`顺手切断既有继承，不默认全仓格式化。

StyleCop解决团队已商定的组织/风格问题，不解决所有权/可维护性证明；SA1402不应成为任意拆文件重构授权。Roslynator有条件Unity回调保护，但未核验完整开关与发布包；unused删除类CodeFix须先查资产、反射、Unity消息和条件编译。禁无人值守删除式Fix All。

### 架构断言 N1与已有边界

先看现有asmdef/编译约束是否已表达问题，避免为一个简单边界引新库。若需NetArchTest，使用显式程序集或marker，不用“当前进程加载了什么”当全集；断言选中类型非空、关键类型在内，并加入已知违规负例证明规则确实失败。固定方向为“source不得依赖target”，不是交换两个namespace仍等价。

程序集类型规则不自动覆盖scene/prefab/Addressables引用，也不证明层次设计合理。N1维护陈旧与Cecil非公开耦合是采用成本，不能以未归档当活跃承诺。

## 5. 验证层次与通过条件

| 层次 | 可以支持的限定结论 | 不能升级的结论 |
|---|---|---|
| 格式/选定静态规则 | 对该输入/配置的规则无新增违例 | 设计正确、生命周期安全 |
| 普通.NET纯逻辑测试 | 指定纯逻辑夹具行为通过 | Unity编译/资产/Player通过 |
| Unity Editor编译/EditMode | 该版本编辑器与所选测试路径通过 | PlayMode时序、所有平台正确 |
| PlayMode/资产回归 | 指定生命周期/绑定/场景行为通过 | IL2CPP/AOT/裁剪/设备行为完整 |
| 指定Player构建与运行 | 该后端/平台/配置下场景通过 | 所有设备/构建都安全 |
| 目标设备测量 | 同场景与基线下实际记录 | 普遍性能提升或代码更短就更快 |

选择哪几层由变更风险决定，不是每次命名修正都跑完整设备矩阵。测试报告必须与最终diff、Unity版本、运行配置关联：新鲜结果文件、测试选择、实际数量/预期关键用例、fail/skipped/inconclusive、超时、进程退出状态及完整日志。命令返回0但未执行目标测试不算通过；流程自然结束也不算（H2终态风险的通用教训）。

F2缺口使本轮不提供`-runTests/-quit`等组合的可运行保证；后续先读实际版本文档并在沙盒验证退出/报告协议。这里没有运行任何Unity命令。

## 6. TDD与旧成果的复用接口

若项目允许，纯逻辑修复先写可观察失败断言并取得真实红结果，再最小修复取得绿结果，最后重构并重跑。生命周期问题需实际宿主夹具；不能用mock纯C#通过替代OnDisable/Destroy契约。红失败若来自环境/编译错误，要区分与目标行为失败。不得写了测试却未执行就标TDD完成，也不预设80%覆盖适合所有模块。
