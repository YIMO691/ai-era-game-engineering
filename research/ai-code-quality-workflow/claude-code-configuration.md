# 配置设计与作用域

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

**本文仅含待审设计与提示模板，不是已写入或已生效的Claude Code配置。** 不修改user settings、全局Hooks/MCP或真实工程。依据O1/O2/C1/E1，完整宿主docs读取失败见F1；因此不凭示例保证全部Rules路径匹配、导入、覆盖顺序和Hook schema。优先用“明确读文件＋回述约束”而非依赖未知自动加载。

## 1. 职责与放置原则

| 载体 | 应放内容 | 不应放内容 | 当前状态 |
|---|---|---|---|
| 项目CLAUDE.md候选 | 项目入口、模块边界、硬契约、验证入口、停止条件 | 整本质量指南、所有API文档、个人审美、密钥 | 仅下文模板；未写入工程 |
| 按需项目文档 | 架构事实、案例/清单链接、决策记录、版本兼容 | 和CLAUDE重复的多份真相 | 后续复用已有位置，不规定新目录树 |
| 任务简报 | 本次目标/非目标、允许范围、状态owner、验收 | 永久全局指令 | 放任务记录即可 |
| Rules候选 | 真正局部适用的约束 | 以规则文件替执行检查 | F1语义未全验，先显式读对应文档，不给可启用路径匹配配置 |
| Skill | 可重复、可评估、现有能力不足的步骤封装 | 一句“写好代码”或重复指南 | 暂不创建专用Skill |
| Subagent | 有明确边界的只读风险审查/独立资料读取 | 每任务固定全员、自动写/自动提交 | 按需；主线程负责事实核验 |
| Hook | 将来触发已验证的固定检查/提醒 | 取代权限、自动等价证明、Post动作回滚 | 当前不启用、不提供JSON |
| settings / user层 | 需另批的宿主设置 | 由研究顺带写allow-all/跳过权限 | 不访问不改 |

不要将Vault的私有研究绝对路径直接写入公开项目配置。真实团队项目应链接获准可共享的本地工程文档；私有参考由使用者显式提供。公开插件许可也不授权公开旧研究或业务代码。

## 2. 短项目契约候选正文

下列是**原创语义模板**，占位符必须由授权项目事实替换。不是安装文件，不保证Claude自动发现。

```markdown
## 项目工作契约（候选）

- 范围：只改本次批准的目录与行为；不顺手升级依赖、公开API或重排全仓。
- 数据：仅将<获批材料>交给<获批模型服务/部署>；禁止额外服务和范围外上下文。
- 全本地保密要求下，未确认环境符合要求前不读源码进入模型上下文。
- 开始前读：<实际架构入口>、<模块边界>、<验证入口>及本任务相似实现。
- 简报：列真实入口/调用链/状态owner/资源交接、非目标、拟改文件与验收。
- Unity约束：尊重现有序列化、启停/销毁、主线程、异步有效期和资源所有权契约。
- 未知先标明；涉及契约/范围/权限变化先确认。不要把.NET建议当Unity事实。
- 实现最小可验证切片。设计讨论、风格清理与行为修复分开。
- 验证：按<本项目已核对命令表>执行；保留命令、退出码、报告和未运行原因。
- 审查：具体输入/状态→失败路径→后果→file:line；硬缺陷/设计/可选风格分开。
- 修复后重新验证；不得用AI自评、旧报告、零测试或skipped声称通过。
- 不自动提交、推送、评论、向批准模型通道以外发送代码、安装服务或改全局配置。
```

长度目标不是固定行数，而是能被一眼执行的少量决策约束；细节放按需资料。该文本只能约束模型行为，不是OS权限边界。若工程已有CLAUDE，先读并提增量diff，不追加第二套互相矛盾的契约。

## 3. 编码前提示模板

```text
先只读。目标：<行为>；非目标：<不做事项>；允许范围：<路径>。
明确读取 <项目契约>、<架构入口>、<相关代码/测试>；只访问本任务需要内容。
从入口追踪到状态改变与副作用，给file:line；指出状态owner、生命周期、
资源接管/释放、错误与取消约定、相似实现，以及尚未读到的资产/平台条件。
按当前风险只读旧指南/案例/清单的相关部分，不加载整套资料。
给最小方案、拟改文件、行为不变项、验证矩阵与停止条件。
当前不要修改；获批后实施。不要把未读/未运行写成已确认。
```

新功能/契约变化采用这个闸门；已清楚授权的小修不必机械再问“能否开始”。未知业务意图或越界才停。参考feature-dev O1，但不复制其完整多Agent流程或JS规范。

## 4. 只读审查与简化必须分开

### 只读审查任务模板

```text
只读审查给定最终diff及必要上下文，禁止修改、提交、网络评论和再委派。
材料：<范围/硬契约>、<base与diff快照>、<验证命令与结果>。
重点风险：<例如启用期事件与迟到回调>，不要排除依赖特定state的问题。
每个发现写：位置、具体输入/状态、执行路径、后果、违反的契约、
证据或待核验项、最小修复建议、验证方法。
硬缺陷 / 设计讨论 / 可选风格分开；严重性与确信程度分开。
不要重新报告程序已覆盖的风格噪声，不用自评分代替运行。
没有足够证据就不报硬缺陷；零发现不等于无缺陷。
```

主线程随后核验，而非自动采纳。新会话/角色可以降低作者锚定，但仍是AI判断；不能把它写成独立效果认证。

### 可选简化任务模板

```text
先只给提案，不编辑。范围仅限<已修改文件/片段>。
行为不变项：<序列化名字/事件时序/生命周期/资源与线程等>。
指出当前具体阅读或修改成本，给一个最小diff备选和“不改”的理由。
不要引入模式/公共工具来合并仅表面相似代码；不套JS/React规则。
获批才改；改后重新执行受影响验证。等价无法确认就停止。
```

若调用的原版simplifier会主动编辑，仅提示“先只读”不足以成为权限保证；选择真正只读工具边界或不加载该agent。不能把toolkit所有角色统称只读。

## 5. 插件加载与冲突处理

已实测的是**help参数**，不是插件运行（C1）：

```bash
claude --version
claude --help
claude plugin install --help
claude plugin marketplace add --help
```

这些只读探测本轮已经执行，无需为研究再跑。`--plugin-dir`仅本会话加载帮助已确认；下列仅为后续批准后的形式示例，**未执行**：

```bash
claude --plugin-dir "<经批准、已静态审阅的单插件目录绝对路径>"
```

不要复制占位符运行。新会话、模型调用和插件工具可能有费用/外发/写入；临时加载并不隔离这些效果。固定源码快照不等于一个经验证可加载的完整包，不能直接拿缓存拼出安装保证。

未来操作顺序：核对当前项目已启用清单与同名命令/agent → 选一个完整固定版本 → 审阅定义、脚本、依赖/网络 → 明确项目/会话作用域和撤回 → 在授权沙盒验证最小调用。不要为了研究官方code-review而调用当前会话同名Skill，那会真的启动当前实现，且不证明二者相同。

**作用域陷阱：** install和marketplace add默认user；install `--marketplace`发现未注册源会先写user settings，即便install scope=project也不能假设无全局改动。本题不运行add/install，也不提供省略审查的一键命令。若未来需注册源，先审当前版本help、明确项目scope及目标文件，再批准具体操作；不使用`--yes`、bypass或自动接受命令源。

## 6. 确定性检查与Hook的界面

最小方案先显式执行已有检查，不需要Hook。批准后若考虑Hook，先明确事件时机、执行器、工作目录、路径范围、超时、幂等性、退出码传播、报告位置、Windows行为和失败策略，并测试正例/反例/超时/解析失败。不能只把命令塞进JSON。

- O1 Hookify导入/处理异常fail-open；不适合未经评估就称硬门禁。
- E1 quality-gate字符串归一化exit0；strict不是阻断证明。
- PostToolUse发生后不能撤销已写文件/外发，Stop也不能证明工作无误。
- 检查失败应由真正执行链阻止后续发布步骤；人类也不应因提示显示绿色而忽略非零/缺报告。
- 不让Hook后台自动format大范围文件、安装依赖或发送私有diff。受影响范围与内容必须可追溯。

## 7. 反馈记录而非无限规则

每条拟固化规则记录：`ID / 已确认失败 / 适用范围与版本 / owner / 例外 / 程序或文档载体 / 正反例 / 撤销条件`。先查现有规则能否改写；不自动新建一堆Rules/Skills。检查器能确定的交给程序，判断型知识保持短引用，单次误报不进常驻契约。

配置是否更有效必须按[基线与单因素试点](adoption-plan.md)验证。没有配置文件写入、插件加载、触发实验或质量效果结果可以在本轮报告为通过。
