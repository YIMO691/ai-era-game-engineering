## 2. 正文关键论断的身份

| 编号 | 正文主张／内容 | 身份及成立范围 | 禁止升级成的表述 |
|---|---|---|---|
| F01 | 生产力改善应扩大把工作做好的可能性 | 本文价值选择，不从生产率事实推出道德义务 | 科学已经证明组织必须把AI节约全部投入品质 |
| F02 | 内在满足、对他人的责任与经济收益需要区分 | 分析框架；允许这些动机冲突，不是开发者动机的穷尽分类 | 所有工程师都因这些原因追求品质，或某动机更高尚 |
| F03 | 审美偏好、可读性感受、理解结果、变更表现和产品品质应分别判断 | 工作性概念区分；未主张统计或因果独立 | 美感与可维护性无关，或它们已被证明为独立构念 |
| F04 | 少行数、更多抽象、更多测试不能单独保证相关品质 | 对逻辑蕴含的限制；不否定这些手段在特定条件下的价值 | 少代码不好、抽象普遍有害、测试没有价值 |
| F05 | 抽象应与变化、隔离、权限及其他明确目标一起讨论 | 条件化工程建议；理解成本不是所有抽象价值的唯一判据 | 每层抽象必须提高阅读速度才有存在资格 |
| F06 | 异常暴露、待处理工作控制、小范围反馈可以作为软件改善候选 | 本文迁移假设；没有以制造业资料证明软件效果 | 精益在软件中一定有效，或某年代的综述代表当前全貌 |
| F07 | 只检查“面板现在打开”不足以满足所给旧回包契约 | 在正文明确的串行事件、打开周期和请求时序假设下的逻辑反例 | 已验证Unity具体API、线程安全、资源释放或生产正确性 |
| F08 | Panel与RequestGate各自有候选收益和代价 | 未运行、未让读者完成任务的结构比较 | B比A更易理解，A比B更快，或者二者已证明行为等价 |
| F09 | 一个环节变快，不足以推出相同交付边界下总成本下降 | 逻辑与核算边界说明，不给出净影响方向或幅度 | AI普遍提效，AI普遍减速，或速度百分比就是质量改善 |
| F10 | 净节约、资源再分配、干预有效是“AI红利转为品质红利”的必要环节 | 本文对该路径的条件分解；不是品质改善的唯一来源 | 品质整改必须等AI先产生节约；投入越多一定越好 |
| F11 | 实现与测试可能共用同一遗漏，输出数量不保证独立性 | 以UI错误前提构造的可能失败机制，不报告发生率 | 已测得AI测试普遍失效，或换模型必然得到独立证据 |
| F12 | 可选品质投资应允许保持现状、缩小范围和停止 | 决策提案，不是拟合的ROI定律；硬约束未满足时须另寻有效方案 | 不好算收益就可以放弃必要安全整改 |
| F13 | 代码优美论可以只是组织问题的名字 | 明确保留理论冗余这一反命题 | 已经创立独立学派或具有新的已验证理论贡献 |

正文没有以以上条目取代领域判断。工程建议需要结合真实的需求、责任分工与风险使用。

## 4. 主动不写入最终稿的内容

1. **未闭合的研究数字**：包括美学相关系数与平方、工艺分类计数、精益非实证比例、AI提效／减速百分比与标准误。删去它们不会损坏本文的逻辑主线。
2. **未直接核对的标准列表**：不列ISO产品质量特性的具体条款数和译名，避免把它变成审美量表或合规证明。
3. **未经考证的线性思想史**：不讲“制造业先有生产率、后有品质”，也不把多个传统写成必然演进的单一路线。
4. **待实施实验的预期结果**：不把T01—T13写成运行通过，不把A/B纸面材料写成已验证行为等价，不给出理解速度或教学效果。
5. **无依据的工具时代结论**：不预言人只剩提需求，也不宣称AI永远无法承担架构或审查；责任归属与工具能力分开。
6. **带精确权重的品质总分**：不将审美、可维护性、可靠性和性能合并为未经校准的统一评分。
7. **无限前置任务**：不要求为了交付这篇文章先补完所有书籍、建立实验平台或招募样本。

上述取舍不是裁定相关资料错误，而是本文不需要依赖这些尚未闭合的断言。

## 5. 后续证据什么时候值得重新打开文章

只有新证据会实质改变正文的判断时，再启动修订。例如：某个真实任务显示抽象方案增加了未预计的负担；独立实验给出限定情境下的理解或修改结果；原文核查推翻了准备采用的事实陈述。
