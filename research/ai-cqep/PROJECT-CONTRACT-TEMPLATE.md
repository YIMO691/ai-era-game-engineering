# AI-CQEP 项目工程契约模板

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

> **先复用现有规范；只有缺少必要事实时才用此模板补缺。** 项目工程契约是一组有效约束，不要求存在名为 PROJECT-CONTRACT 的文件。已有项目指令、规范导航、架构资料和验证入口足够时，直接使用，不复制填写一份新契约。
>
> 以下是候选模板，不是任何真实工程的事实、授权或可执行配置。`<待填>` 不能作为命令执行，示例不是默认值；新增政策须由有权维护者确认，已生效的规则无需为采用本协议重新审批。

通用决策与证据义务见 [核心协议](AI-CQEP.md)；日常执行见 [精简协议](QUICK-REFERENCE.md)；接入 Claude Code 见 [采用说明](CLAUDE-ADOPTION.md)。

## 使用方式：已有入口优先，缺口按需补充

- **已有规范足够：不填写、不新建。** 直接按项目导航读取相关约束；同一任务不重复读取仍有效条款，不为证明未变全库扫描或反复算哈希。
- **确有缺口：只补当前需要的事实或入口。** A 节是可选最小导航，B～H 按实际触发补充；不一次填满表格，不写大量“不适用”，关键未知不能假装不存在。
- 已有权威文档、配置和脚本只引用，不抄一份易漂移的副本。事实冲突显式登记，由维护者确认；Agent 不静默选自己喜欢的一版。
- 状态使用 `已核实 / 假设 / 未知 / 不适用`；区分项目批准的政策与实际运行证据。“已批准”不等于“已测试”。
- 每条重要约束要能找到**事实来源、适用范围、负责人及例外**。同一负责人/来源可在章节统一声明，不必逐行重复。
- 未知若决定正确性、责任、授权或兼容，先查证，仍不能消除就阻塞相应实现；无关表达细节可沿项目默认继续。
- 契约应短到值得读取。稳定的一般原则不复制进来；复杂历史留既有决策记录，长期规则留本表入口。

按实际需要补充：

- **状态与不变量：** 哪些状态唯一可写，哪些只是投影/缓存；何处原子提交；何时失效；并发、重入、重复调用如何处理。
- **外部副作用：** 哪个操作可能已部分发生；失败/超时后如何确认；重试、幂等、补偿与最终报告由谁承担。

## 使用门槛：能支撑本次决策即可

已有规范或必要补充能回答**本次**任务“在哪里改、必须保持什么、责任归谁、如何验证、何时问人”即可形成方法级方案，不必达到全项目百科的完整度。常规功能按约定先整体审核方案；契约足够不等于方案已审。关键未知只阻塞依赖动作，已审范围内的其他安全工作可继续。

任务完成仍按核心协议区分：已完成并按范围验证 / 实现完成但验收待验证或待决定 / 阻塞或未完成。提测引用原验收记录中的版本、环境、开发验证/联调、回归与缺口，不重建用例副本。契约被批准、编译通过或审查零发现，不代表 QA 通过、产品验收或发布许可。
