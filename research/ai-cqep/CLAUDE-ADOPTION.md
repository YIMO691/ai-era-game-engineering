# 在 Claude Code 中采用 AI-CQEP

> 公开导出说明（2026-11-12）：以下为原稿研究或通用模板，不是实际配置；历史状态、检查与未运行项不因公开授权而升级。来源与排除边界见 [README](README.md) 和 [导出清单](export-manifest.json)。

**采用目标：让 AI 先交一份有项目依据、细到关键方法的方案，人审后按范围实现，审查与联调完成后提测。不是让用户每次提醒 AI 跑协议。** 默认零新增 Skill、Agent 定义、Hook、插件或服务，复用项目已有规范、任务记录、功能手册与验证链。

本文是采用提案，不是已应用配置或自动门禁。只修订四份研究文档，没有修改业务项目的规则、代码、权限、全局配置。自然语言指令不提供操作系统隔离，也不能保证模型自动遵守。

[核心协议](AI-CQEP.md) 按需查阅；[精简工作流](QUICK-REFERENCE.md) 用于快速了解；[契约模板](PROJECT-CONTRACT-TEMPLATE.md) 仅补现有工程事实的必要缺口。四份不是每任务必读清单，也不要求全部搬入项目。

## 1. 采用一次，日常给需求，不反复给协议

### 1.1 先确认权限与已有入口

确认允许的目录、副本、材料、模型/服务通道、执行与费用范围。Claude Code 在本地操作文件，不代表模型推理全在本地；读取源码可能使其进入配置的模型上下文。不启用 CodeRabbit 不等于全本地，已批准模型通道也不自动批准其他服务或部署。

按宿主实际机制读取已有项目指令和规则导航；不假设某文件名必然自动加载。相关规则已在有效上下文中就复用；缺失、改变、矛盾或进入新领域时，仅补读相应部分。不把“已读”标记当成条款本身。

### 1.2 确认一次工作约定，不先建设新体系

- 常规功能先拆业务、查工程、给方法级实施方案，人工确认后编码；批准后按功能点自主推进，重要差量再审。
- 已授权局部小修可以短简报直接修复并验证；咨询和文档任务按实际范围处理。
- 稳定项目规则直接执行，用户不必重新审核命名、排版、注释、分层等已有约定；AI 仍需对本次如何符合它们负责。
- 有现成规范就不建 PROJECT-CONTRACT；有原功能手册就不另建统一方案库；有任务记录就不新建六份阶段报告。

若项目当前默认“信息足够后自主编码、不固定增加审批”，本协议不会自动改变它。应由有权人员明确本次任务或采用范围使用“先整体方案审核”；未获规则维护授权不修改 AGENTS、WORKFLOW 或远端 SOP。

初次可仅在当前任务明确上述方式并提供规范入口，无需安装或改配置。长期采用时，优先对现有入口做经批准的最小补充，不新建固定目录树；当前研究路径不硬编码到其他项目。

### 1.3 用一个真实功能检验，不先宣称收益

选择一个边界明确的功能，核对方案是否足以审核、实现是否受控、联调是否覆盖需求、提测材料是否可用，并记录总成本和人工返工。再看不同风险任务是否需要调整，不同时换模型、加插件和全量重构。评估方法见核心第 11.2 节；当前未试点、未验证质量收益。

## 2. 可供项目确认的短入口候选

下面是工作约定候选，不是已经应用的补丁、Hook 或自动加载配置。只有项目缺少相应约定时才增量加入原入口；不要覆盖已有更严格规则，也不要求每次任务粘贴此段。

```markdown
## 功能开发工作方式

- 稳定项目规范主动落实；按需读取相关规则和源码，不重复加载仍有效内容。
- 常规功能先按可验证业务结果拆点，明确非目标、依赖与验收；查真实入口、
  同类实现及状态/资源/副作用边界，给出方法级实施方案后等待一次整体人工审核。
- 方案关联功能、预计新增/修改方法、职责与关键输入输出/顺序、项目与源码依据、
  选择理由、风险及验证。事实、设计理由、待验证分开，不把方案写成当前实现。
- 批准后逐功能点贯通必要代码、配置/协议/资源、注释整理、验证和文档同步。
  普通内部细节自行处理；业务、验收、公共接口、职责/所有权或授权的重要差量再审。
- 已授权且边界明确的局部小修可简记直接修复；不据此绕过常规功能方案审核。
- 按风险增加调查、检查与必要独立审查，不默认增加 Agent、审批或新工具。
  作者自查不冒称独立审查，另一个 AI 同意也不是运行证明。
- 最终分别核对代码质量与需求符合性，完成适用开发联调，修复后更新证据；
  提测交接列明版本、验收入口、环境、验证/联调、回归范围和缺口。
- 必要项未完成不无条件报提测就绪；开发验证不替代 QA、产品验收或发布批准。
  本入口不新增提交、推送、发布、外发、安装或修改权限/全局配置的授权。
```

普通命名、拆函数、注释和结构组织由 AI 按规则决定；人审核目标、边界、关键实现与证据，不替 AI 执行整套编码检查。入口不是执行器：仍须通过实际改动、验证和审查发现偏差，不能声称它构成技术门禁。

## 3. 日常如何发需求、审核和接续

### 3.1 第一次给功能需求

约定已经生效后，日常只需给原需求及必要限制，例如：

```text
按项目既定方式处理这份需求：<需求正文或现有文档入口>。
本次允许范围/非目标：<与平时不同的限制；没有新增限制可不另写>。
先给可审核的功能拆解与方法级实施方案，不先改业务代码。
```

不必每次复制八条原则、完整协议、命名约定或全部手册。最后一句适合首次采用或需强调先审后写时；项目已有可靠约定后也不必反复追加。

AI 的方案应复用既有文档，至少建立：

```text
功能点/验收 → 方法落点与复用/修改/新增 → 输入输出、主流程与适用失败收尾
           → 项目/源码事实、选择理由、关键未知 → 检查及真实联调方式
```

列清预计新增/修改的方法；关键方法细写，简单辅助方法简写。整体审核看覆盖与非目标、职责/复用、状态和资源协议、必要配套、兼容/风险、验收与待定事项；不是逐方法单独批准，也不要求提前写好全部代码。

### 3.2 审核后推进

```text
同意 <方案版本或所在记录>，按其中范围和依赖顺序实施。
逐功能点完成必要配套、代码整理、验证和文档同步后继续下一点。
普通内部细节自行处理；重要差量只提交变化、影响和验证安排供审核。
```

只有真实获得人工确认后才能记录“已审”。未得到回复、AI 自审、另一个 Agent 同意都不是用户批准。方案确认不等于同意删除数据、提交代码或发布。

已授权小修可直接给出故障输入、预期、不变项和范围，要求最小修复及真实验证，不另走完整功能方案。风险/责任发生变化时先补调查，出现重要差量再审，不靠“小修”标签掩盖新增功能。

## 4. 私有项目映射未公开

原稿本节是私有项目与配套文档的具体映射，公开分发权未明确，因此整节排除。通用采用建议保留在其他章节；此处不是可公开复核的项目案例，也不证明任何项目已采用该协议。来源缺口见核心协议附录 A 的 R4。

## 5. 代码审查与验证：复用现有链路

作者必须检查完整受影响方法及必要调用方，主动完成命名、注释、结构和排版整理，不等用户调用专项 Skill。Review 同时看代码质量和需求/方案符合性，不能只看差异几行或测试数量。

独立审阅按核心第 4.6 节选择：L 可不额外启用，M 按主要风险，H 默认需要未参与实现的审阅者。优先项目已有人员，不默认新建 Agent。若确需获准的新 AI 上下文，可用以下只读提示，不发送作者的“已经正确”结论：

```text
只读审查 <最终改动范围>，不要改文件、联网、委派、提交或运行有副作用命令。
需求/验收、已审方案、项目约束、必要周边、已有验证：<原事实入口>。
聚焦本次真实风险，并核对命名、方法职责、注释、主流程和范围控制。
自行追实际路径，不预设必须有发现；区分必须修复、设计讨论、可选风格。
每项给位置、对应契约、具体条件/路径、后果、证据及最小建议/验证。
保留未知，允许零发现，但不由此推断无缺陷或可发布。
```

这不是权限沙箱；工具权限、材料通道与预算另行核对。主线程逐项接受修复、有依据反驳、待补证或范围外交接；本次引入或直接影响验收的必须修复项不能以范围外绕过。

验证优先项目已确认适用的入口，不提供一条通用 dotnet/Unity 命令替代实际工程链。不从脚本名、日志心跳、退出码 0 推断通过；核对非空对象、关键用例、新鲜报告和终态。保留失败/跳过/未执行，修复后更新受影响结果，不临时安装依赖或启动真实业务服务补齐仪式。

开发联调按原业务入口，核对实际加载的双端或相关模块代码、协议、配置、资源和环境，逐验收记录结果。单端、编译、mock 和受控替身通过各有价值，但不能替代未发生的联调；环境不可得就明确待验证。

## 6. 提测交接、反馈与退出

交接引用现有功能和验收记录，简短列明：

```text
交付状态：开发完成并按范围验证 / 实现完成但验收待验证或决定 / 阻塞或未完成
交付版本、功能/非目标、方案版本与重要差量：<实际事实>
验收与测试入口、环境/必要数据：<引用既有资料，不含凭据>
实际验证和开发联调：<受检版本、步骤、环境、结果、证据及未覆盖项>
代码审查：<自查/独立审阅的真实范围、发现处理和复验>
回归范围、已知问题、剩余缺口与下一步：<具体影响与接续动作>
提测：<满足约定才报就绪；否则待验证，或经有权人员接受缺口后受限移交>
```

开发完成不是 QA 通过、产品验收或发布许可；开发联调不能宣称“完全不存在遗漏”。没有新知识不加复盘文件，仅将确认且可复用的反馈补到已有契约、测试或检查器，保留原因、范围、例外与解除条件。

负担变大时先删重复记录和无决策价值内容，不先加规则、Agent、Hook 或平台。撤回采用也只处理获准加入的入口和试点内容，保留用户后续修改；已有有效修复、测试和工程事实不随流程盲目回滚。本文未启用服务，不存在默认新增服务需关闭。

## 7. 迁移到其他 AI 编码 Agent

保持通用协议与项目事实分层：迁移需求→方法方案→整体审核→受控实施→验证/审查→交接的责任和证据要求，不搬运 Claude 专属入口。项目规范不因换 Agent 另抄一遍。

单独核对新宿主的指令加载、工具权限、模型通道、费用、执行终态与安全限制；不要假设它识别 CLAUDE.md、Skill 或相同命令。重新用代表任务观察行为，不外推尚不存在的采用效果。
